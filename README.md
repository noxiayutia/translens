# TransLens

沉浸式网页翻译扩展：**默认只显示译文**——页面上看不到原文，也就不会有两种语言互相挤占版面。
原文并没有被删掉，它只是被藏了起来（同样在 DOM 里），随时可以一键还原，也可以在弹窗里切回双语对照。

- Manifest V3，Chrome / Edge 可用。
- **装完先配一个翻译引擎**：扩展**不预置任何引擎**，也没有内置接口——配一个自己的 OpenAI 兼容接口
  （DeepSeek / OpenAI / 本机 Ollama 都行），见「安装」里的**「快速开始」**。
  （早先那版自带"免费的 Google 翻译接口、装好即用"，**这个功能已经删掉了**：它不稳定、可能被限流，
  而且为了让扩展能访问它，安装时还得索要一个站点访问权限。）
- 译文以纯文本写入页面的 Shadow DOM，不影响原页面样式。
- 两种显示模式：**仅译文**（默认）/ **双语对照**，弹窗里随时切换。

## 安装

```bash
npm install
npm run build
```

然后在 Chrome 里加载：

1. 打开 `chrome://extensions`
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选择本仓库的 **`dist` 目录**（注意是 `dist`，不是仓库根目录）

加载成功后扩展会出现在扩展管理列表与工具栏的拼图菜单里，名字是 **TransLens**，图标是一个蓝色
圆角方形、里面两个薄荷青的双向箭头（左右各一个、上下错开，表示"两种语言互换"）。图标是
`src/icons/` 下入库的四个 PNG（16/32/48/128），由 `scripts/make-icons.mjs` 从零生成（只用 Node
标准库，不依赖任何图形库），改了设计就跑 `npm run icons` 重新生成（脚本会自检：读回、尺寸、
CRC、四角、底色与两支箭头，不对就非零退出）。

品牌 logo（两个相交的透镜圆 + 中间的白箭头，给扩展详情页/官网用）是**另一张图**，体积更大、
细节更多，由 `npm run logo` 生成到 `docs/brand/translens-logo.png`。两者不共用一张图是有原因的：
**16px 只承载得下"一个形状 + 一个方向"**，两个圆加一个箭头在工具栏尺寸下必然糊成一团
（圆环会被笔画填实、白箭头压在白圆上会消失），所以小图标退回"双向箭头"这个在四个尺寸下都
验证过的符号。`scripts/make-icons.mjs` 顶部记了这三种失败走法的具体数字。
`dist/` 只在 `npm run build` 之后才存在，且已被 `.gitignore` 忽略。

> `npm run build` 的最后一步会自动运行 `npm run verify:dist`（见下文「验证」），
> 它不通过时构建会以非零退出码失败——所以 **「构建成功」就等于「产物可加载」**。

### 快速开始（装完先做这一步）

装上之后**插件没有任何可用引擎**——它不会替你选一个，也不会偷偷用一个内置接口。
第一次翻译之前先配一个自己的服务商档案（四步）：

1. **打开设置页**：点工具栏图标打开弹窗 → 点右上角的**齿轮**（也可以在 `chrome://extensions`
   里点这个扩展的「扩展程序选项」）。
2. **新增一个档案**：在「翻译引擎」区块点 **「+ 新增档案」**，填一个**名字**；在展开面板的
   「自定义设置」区里选一个「服务商模板」（OpenAI / DeepSeek / Ollama（本机）），接口地址与
   模型名会自动填好——也可以全部手填（新档案的地址为空时，这块会替你自动展开，不会藏起来）。
3. **填 Key、选定模型**：填 **API Key**——**扩展要求这个字段非空**，哪怕服务商本身不校验它
   （接 Ollama 这类本机服务时随手填个占位值即可）。「模型目录」里**至少要有一项是「当前」
   模型**：点「⟳ 获取可用模型」勾选后并入，或点「+ 添加模型」手填一个——清单原本是空的，
   加进来的第一项会自动设为「当前」，之后再换点「设为当前」。可以顺手点「测试连接」确认
   这条链路真的通（它真的会翻一次 `hello`）。
4. **点「保存」并允许授权**：这一步会弹一次浏览器授权框，问你是否允许访问你填的那个地址——
   **必须允许**，否则发往该地址的请求会被浏览器拦下（拒绝也不影响保存，之后再点一次「保存」
   即可补授权）。

回到弹窗，在「翻译引擎」下拉里**按名字选中**刚配好的那个档案，然后按 `Alt+T` 或点「翻译此页」。

> 一个档案都没配时，弹窗里**不会显示「翻译引擎」这一行**，提示区会说
> 「还没有可用的翻译引擎，去设置页添加一个服务商档案。点右上角齿轮打开设置页」——
> 这就是首装的状态，不是坏了。设置页的「翻译引擎」区块顶部显示同一句核心话
> （不带"齿轮"尾巴），区块右上角就是「+ 新增档案」按钮。

## 使用

| 操作 | 效果 |
| --- | --- |
| `Alt+T`（可点 `chrome://extensions/shortcuts` 改键） | 翻译当前页面；再按一次完全还原（原文一个字符都不会变） |
| 点击工具栏图标 | 打开弹窗：翻译此页 / 显示原文、切换**显示模式**、**悬停/划词开关**、切换**目标语言**、切换**翻译引擎**（按档案名字直接切；还没配过档案时这一行不显示，提示区会指路设置页） |
| 弹窗右上角齿轮 | 打开**设置页**：顶部一个「搜索设置」框 + 左导航三段（翻译 / 内容控制 / 数据）共 8 个区块——翻译引擎（**服务商档案管理**：列表展开编辑 / 新增 / 删除，可从 OpenAI / DeepSeek / Ollama 模板预填；逐个档案的**测试连接**与状态点）、语言与显示（含**源语言**）、快捷翻译（悬停 / 划词开关）、术语表、站点规则、提示词、缓存与请求、隐私 |
| 右键菜单 · **翻译此页** | 翻译当前页面 |
| 当前站点被规则设为「永不翻译」 | 弹窗里出现一行状态 **此站已设为「永不翻译」· 解除**；点「解除」只撤掉生效的那一条规则，随后就能照常点「翻译此页」 |
| 右键菜单 · **翻译选中文本** | 弹出划词气泡：译文 + 复制 / 朗读；读不到实时选区时用菜单文本兜底、气泡停在视口中央 |
| 按住 **Shift** + 鼠标悬停段落 | 段落加 outline 描边，约 180ms 后在浮层气泡里显示该段译文；移出保留、重复悬停命中缓存。**按住 `Alt` 时悬停暂停**——诊断手势按着 `Alt+Shift` 移向目标，沿途每一段都不该顺手发一次请求（判据取自每个悬停事件自己的 `Alt` 状态，松开即恢复） |
| 鼠标**划词**（选中 1~2000 字符） | 选区下方弹出气泡：译文 + 「复制」/「朗读」按钮 |

> 悬停与划词都是挂在 `documentElement` 上的 **fixed 浮层**：不往页面里插任何节点，
> 高亮用 `outline`（不占空间、不影响布局）。弹窗里的「悬停翻译」「划词翻译」开关控制它俩是否启用，
> 改动即时写入设置，并推给当前页面当场重新挂/摘监听器（详见下）。

工具栏上的图标就是上面那个「蓝色圆角方块 + 薄荷青双向箭头」。**如果没看到它**，点拼图按钮把
「TransLens」固定到工具栏即可（新装的扩展默认收在拼图菜单里，这是 Chrome 的行为，与有没有图标无关）。

### 显示模式

| 模式 | 页面上的样子 | 什么时候用 |
| --- | --- | --- |
| **仅译文**（默认） | 每个段落只剩译文；原文被包进一个 `display:none` 的 `<span>` 留在 DOM 里 | 不想让两种语言把版面挤满 |
| **双语对照** | 原文照旧，译文插在每一段下面 | 想对照着读，或者需要点段落里的链接（多链接段落仅译文下仍点不了） |

两处都能改：**弹窗最上面那一栏**（改完立即写进本机存储），以及设置页的「语言与显示」（改动即时保存）。

> **改完不会自动重译当前页面。** 显示模式是在翻译**开始时**读一次设置，已经译好的页面要重新翻译
> 才会换过来（按 `Alt+T` 还原、再按一次翻译）。弹窗会如实提示"重新翻译此页生效"，不会假装已经生效。
> 这样也不会把已经译好的内容悄悄丢掉。

### 增量翻译（页面译好之后新出现的内容）

**页面翻译之后，新出现的动态内容也会被翻译**：内容脚本挂一个 `MutationObserver`，
X/Twitter 这类无限滚动站点向下滚出来的新推文，会像普通段落一样出现译文。行为与边界：

- **只在页面已翻译后生效。** 没翻译之前页面随便怎么变，一个请求都不发；按 `Alt+T`
  还原的瞬间观察者断开，之后的新增内容不再翻译（点击页面也一样不再触发任何扫描）。
- **观察的是整个文档（`<html>`），不只是 `<body>`。** 有些前端框架会把浮层/菜单挂到
  `<html>` 下、成为 `<body>` 的**兄弟**节点，只盯 `<body>` 的观察者一个字节都看不见——
  这类内容连"新增节点"这个信号都不会出现。提到文档根之后噪音更多（插件自己的浮层就挂在
  那里），由既有的两道防护挡下：属性路径对 `[data-jy-root]` 子树一票否决，节点路径上
  新增的译文宿主被采集端整体短路。
- **有可见延迟。** 变动攒 500ms 防抖再处理（无限滚动拨一下滚轮就是几十次变动，
  逐次处理就是翻译风暴）；所以新内容的译文大约晚半秒到一秒才出现。处理期间新来的
  变动会合并到下一轮，不丢、也不会两轮并发互相打架。
- **每轮最多 60 段**，一次大变动攒下几百段时分几轮送，接口不会被一口气打爆。
  请求数与新增段落数成线性关系（有单测按"50 轮 × 每轮 20 段"模拟无限滚动了钉住）。
- **只扫新增的那棵子树**，绝不重扫整页——3000 段的长页面每次 DOM 变动都全页采集
  会把主线程打满。新内容长在"直接文本和块级元素混排"的容器里时改扫该父容器，
  否则那段直接文本会被漏掉；同容器重复出现的同一段文本（松散文本没有防重扫标记）
  由增量层的 (容器元素, 段文本) 账本去重，不会二次插宿主；不同容器恰好同文的段落照翻。
  这条"只扫新增"是硬约束：**整页重扫绝不接进变动路径**（下面那条兜底除外），
  有专门的用例按采集次数断言"只改 DOM、不加交互时，采集次数与改动前完全一致"。
- **悬停/点击展开的下拉菜单、折叠面板也会被翻译。** 这类结构（如 nature.com 顶部导航的
  "Explore content"）内容**本来就在 DOM 里**，展开只是切 class 改可见性、没有任何节点增删——
  观察者在 childList 之外同时盯着 `class` / `style` / `hidden` / `aria-hidden` / `inert`
  这些能改变可见性的属性（用 attributeFilter 圈定，`data-*` 之类的埋点改写**连队列都进不来**；
  改 `class`/`style` 的动画与埋点仍会入队，但会在回调里被廉价判据当场丢掉），
  当被改动元素连同它的祖先**从不可见变为可见**时，扫描该元素的子树并走完全相同的翻译链路：
  同一个 500ms 防抖窗口、同一本去重账本、同一个单轮上限。仍然隐藏的子树上的改动**零扫描**；
  反复开合同一个菜单不会让请求增长。两处如实的边界：收起动作**一定不发请求**，但当站点把
  开关类切在一个始终可见的祖先上（nature 就是这种形态）时，会付一次结果为 0 段的空扫描
  ——因为不比对旧状态就无法知道"里面整棵子树变隐藏了"；折叠面板那种把 `display` 切在容器
  自身上的形态则收起时零扫描。另外可见元素上纯粹改样式的 class 变化（hover 高亮）与
  "变可见"在原理上不可分辨，也会付一次对着已译子树的空扫描。两者都只花一次函数调用，
  不产生请求。
  还有一个覆盖不到的情况：展开若纯靠 CSS `:hover` 选择器实现（页面不写任何属性），
  观察者没有信号源，只有站点用 JS 切类/切属性时才生效。
- **用户一与页面交互，就补做一次整页重扫。** 上面那些观察信号有个共同的破口：
  内容出现了、却没留下我们能观察到的痕迹。实证就是 digitalocean 顶部导航的下拉菜单——
  面板由 React 在**点击那一刻**现渲染，六张卡片一个都不在初始 HTML 里，而 childList
  路径什么都没收到（面板被 portal 挂到了 `<html>` 下、或站点只切了我们没盯的属性、
  或面板早已在 DOM 里只是被某个看不见的东西控制着）。与其去猜是哪一种，不如**不再依赖
  "怎么变的"**：`pointerdown` / `click` / `keydown`（捕获阶段 + passive，挂在 document 上）
  任一发生，就在 **400ms 防抖**之后调度一次**与整页翻译完全相同的采集**，靠上面那本
  (容器, 文本) 账本跳过已经翻过的内容，所以它只花时间、不重发请求、不重插宿主。
  两条护栏：**节流**——两次整页重扫之间至少间隔 1 秒，连点不会把主线程占满；
  **元素数上限**——文档元素超过 15000 个时跳过整页重扫（只保留上面那些窄路径），
  因为那种页面上单次整页采集是几百毫秒的量级、挂在每一次点击后面就是卡顿。
  这条兜底**只由用户交互触发，绝不由 DOM 变动触发**（有测试按采集次数锁死）；
  它与增量轮共用同一个防抖定时器、同一本账本、同一个单轮上限，不是第二条处理链。
  如实说明两个代价：超大页面（>15000 元素）上这类"无痕展开"的内容翻不出来，
  需要还原重译；以及每次交互最多推迟 1 秒的那次整页采集。
- **只管"新增"，不管"改动"和"移除"。** 已经译过的段落被前端框架改了文本不会重译；
  译文宿主被框架重建顺手移除时也不会自己回来——这类页面还原重译一次即可。
  具体到"往一个已译好的段落里追加文字"（含追加到它的行内子元素里）：**整段不会被重新
  翻译一遍**，那段新文字也不会单独冒出第二个译文——它属于"改动了已译段落"，按上面的
  范围约定一并交给还原重译处理。（注意这与上一条的整页重扫不冲突：重扫只认账本里没有的
  (容器, 文本)，已译段落不会因为被重扫到就重译。）
- 新内容**沿用当前页已生效的显示模式与目标语言**，中途在弹窗改设置不影响正在增量
  翻译的页面（改动对新页面生效，老页面还原重译）。
- 失败处理与整页一致：该段显示红色错误与「重试」按钮，整批同码错误照常浮出提示，
  不静默。一轮里混着多种错误码时，页面级提示按**优先级择一**弹出（`AUTH` > `RATE_LIMIT` > 其它，
  整页与增量共用同一套判据）：第 1 批缺 Key、第 5 批网络抖动时，弹的是"去设置页填 Key"那条，
  不会被后到的瞬时错误顶掉。

### 诊断模式：点一下就知道「这段为什么没被翻译」

遇到「页面上某一块没翻」时，不用开 DevTools 找元素、也不用复制 HTML——
**在那块没翻的地方按住 `Alt` + `Shift` 再点一下**，页面底部会弹出一条结论，截图发出来就行。

三步：

1. 页面**翻不翻译都行**（两个状态给出的结论不同，这正是它的用处）；
2. 在那块没翻的内容上按住 `Alt` + `Shift` 点击（**普通点击不会有任何反应**）；
3. 看页面底部的提示（**停留 15 秒**——用户的视线在被点的元素上，普通状态提示那 3.2 秒不够
   低头读懂再截图），同时结论已经复制进剪贴板——直接粘贴比截图更准确。

会看到什么（表里这 14 条就是全部结论，没有别的花样）：

| 结论 | 含义 | 下一步 |
| --- | --- | --- |
| **页面还没开始翻译（按 Alt+T 开始翻译整页）** | 这个页面压根还没进过翻译状态 | 按 Alt+T（或点扩展图标上的按钮）先翻整页，翻好之后再点这里 |
| **未采集：这一段还不在已处理账本里（可能是翻译后才出现的…）** | 页面已经翻译过，但这一段从来没进过采集 | 多半是它刚出现、增量那一轮（或点击后的整页重扫）还没轮到它：点一下页面、或稍等一下再看；元素数超过 15000 的页面会在这里写明"可能落在整页重扫的元素数上限之外" |
| **未采集：采集端下钻不到这里（交互重扫永远不会采到，需要修代码）** | 这一段自己会成段，但**从采集根走到它的路上断了**：某个祖先既不是块级、判据又不认为它内部有块级内容（真实形态：连续 16 层以上的纯行内包裹，见「已知限制」） | **等待与重扫都不解决问题**——结论会点名断在哪一级祖先（tag/类 + display，路径里带 `⟨断点⟩` 标记）；把这个结论原样发出来就是修采集判据的现场证据 |
| **已采集未翻译：宿主不存在** | 这段确实采过，但译文没渲染出来 | 请求/渲染环节的问题，把这个结论发出来 |
| **已采集，还在翻译中** | 宿主在，等接口回来 | 等一会儿；一直不变就是请求卡住了 |
| **已翻译** | 这段已经处理过、译文就在那儿 | 若看到的仍是原文，多半是原文没被藏起来，属渲染问题 |
| **未采集：不可见（自身/祖先 … display:none）** | 这块现在是收起的 | 指出是**自身**还是**哪个祖先**引入的隐藏（`visibility` 会继承，所以报的正是"从哪一层开始藏"）——真隐藏不必翻，"展开后没重新扫"才是 bug |
| **未采集：已是目标语言** | 判定这段本来就是目标语言（报告检测到的字符集） | 判定错了就是语言识别的 bug |
| **未采集：文本不合格** | 少于两个字母这类噪声闸挡下的 | 正常，数字、页码、纯标点都走这条 |
| **未采集：这里没有可见文本** | 一个字的可见文本都没有（纯装饰容器、只有图标） | 正常；想翻里面的内容就点更里面 |
| **未采集：这类标签一律跳过（自身 code / 祖先 pre#pre）** | `code` / 表单控件 / `svg` 等；**祖先**是这类标签时整棵子树都不翻 | 有意为之——点更里面也没用，这里就是不翻 |
| **可编辑区域，有意跳过** | `contenteditable` 里的内容（草稿、评论框） | 有意为之：不把没写完的东西送出去 |
| **插件自己的浮层，本就不该翻** | 点到译文宿主或提示气泡上了 | 点原文那一块 |
| **这里不是段落，点更里面的元素** | 这一层是容器，里面每块各自成段 | 照它说的，点更里面 |

结论里的"这一段"按**采集端的归属**算：点段落里的行内 `<span>`、`<b>`，报的是它们所属那一整段；
松散文本段（`<div>Intro<p>Body</p></div>` 里的 Intro）归到容器，宿主也挂在容器上。

提示的第二行是增量层此刻的读数，排查"动态内容没翻"时关键：观察者是否启用、
最近一轮增量是什么时候、采到几段、最近一次**交互兜底整页重扫**是什么结局
（`已执行` / `被元素数上限跳过` / `节流中，已推迟`），以及当前文档的元素数。

另外两个通道：**开控制台**能看到一份 `console.table`，逐级列出"点击处 → 父 → … → body"
每一级的结论与理由；**剪贴板**里是同一份结论的完整文本（结论 + 元素路径 + 目标语言 + 上面那些读数），
可以直接粘贴出去。元素路径是**真实祖先链**（从 body 沿 `parentElement` 走到点击处，链过长时
头尾压缩、但结论级与 `⟨断点⟩` 所在级永远保留）——早期版本曾把没走过的中间层补成一个假的
`body > …` 前缀，把排查引向过完全不存在的父子关系，现由测试逐级反查钉死。

诊断**只在 `Alt`+`Shift`+点击时工作**，其余时候一行代码都不多跑；它也**绝不改变页面**——
不拦截点击、不改 DOM、不发任何翻译请求（有测试按"触发前后 `document.body.outerHTML` 逐字节相同"
和"零请求"钉住）。

## 翻译引擎

| 引擎 | 需要 Key | 说明 |
| --- | --- | --- |
| **服务商档案**（OpenAI 兼容 API） | 是 | 走 `{接口地址}/chat/completions`，可接 OpenAI、DeepSeek、硅基流动、Ollama 等 |

设置页可以配**多个服务商档案**：一个档案 = 名字 + 接口地址 + **模型清单** + API Key（`id` 稳定唯一，
名字随便改不会弄丢引用）。每个档案可以装**多个模型**，其中一个是「当前」——同一家接口的两个模型
不必再复制成两份档案。清单两种加法：点「+ 添加模型」**手填**（空值与重复值不写入），或点
「⟳ 获取可用模型」从 `{接口地址}/models` **拉一份回来勾选**（默认全不选；只有你点那一下才会发请求）。
配好几个档案之后，在**弹窗**的「翻译引擎」下拉里**按名字直接切换**——下拉列出的就是
**每个档案的名字**（引擎不再有内置项），选中即写入本机存储、立即生效。某个档案有 2 个以上模型时，
弹窗里会**多出一个模型下拉**（只有一个模型时不显示：一个只有一项的下拉是噪声）；切回某个档案时
它会记住那个档案上次用的模型。

### 当前版本的真实限制

- **撞上限流时会把这一轮的并发降到 1，再阶梯回升。** 设计文档 §8 那条"429 时临时降并发"
  已经实现：每个批次除了各自按 500ms / 1500ms 退避重试，还会让**本轮的并发池**压到 1 路，
  之后每连续 4 批干净落地（或距降级满 30 秒）才翻倍回升一档，且**永远不超过你在设置页
  设定的并发数**。作用域是"这一轮翻译的池"——不是全局、也不按引擎 id 共享：一轮只用一个
  档案，而跨标签页互不影响（一个页面被限流不该拖慢另一个页面）。
  一次限流风暴里多个批次各自回报 429 只算一次降级，否则恢复进度会被反复清零、页面出不来。
- 档案的接口地址、API Key、**模型清单**在**设置页**里管理（弹窗右上角的齿轮按钮）。点某一行右侧的
  「编辑」展开面板：那里可以改名字与 Key、改接口地址、加删模型并把其中一个设为「当前」，底部是
  「测试连接 / 取消 / 保存」。**「取消」丢弃这次编辑，存储一个字节都不动**。「测试连接」会用该档案
  当前编辑的内容真的翻一次 `hello`（测的就是正在编辑的那一个，不是全局），成功显示译文、失败显示
  错误码。**没有「当前」模型时点「测试连接」或去翻译，都只会得到一句可读的错误，一个请求都不发**。
  老数据（v2 的单份配置）升级后自动折成一个档案、它的单个模型名抬起成"清单里只有这一项"：当时在用
  自定义接口的，名字取自当时选过的服务商；用免费接口的老数据不会凭空长出档案。
  设置版本升到 **v5**：v4 里选着免费接口的，升级后自动切到**第一个配好模型的档案**；
  一个都没有就是"没有可用引擎"（弹窗与设置页都会说出那句话，并指路设置页）。
- **拉取模型清单读的是存储里那份档案**：面板里改了地址或 Key 但**没点保存**就点「获取可用模型」，
  拉的还是存储里那份（后台按档案 id 自己读，设置页从不把 Key 送进消息）。拉取失败按原因分别说明
  （连不上 / 401 / 404 / 不是 JSON / 10 秒超时），**手填这条路永远在**。
- **从服务商模板创建**：档案编辑表单的「服务商模板」下拉，选定即把该行的**接口地址**填好，
  并把该模板的模型名**并入模型清单、设为当前**（防手滑填错）——OpenAI（`https://api.openai.com/v1` + `gpt-4o-mini`）、DeepSeek
  （`https://api.deepseek.com/v1` + `deepseek-chat`）、Ollama 本机（`http://localhost:11434/v1` +
  `llama3`）。这是为消除"把模型名填成 `deepseek`（正确值 `deepseek-chat`）拿到一个看不懂的
  HTTP 400"这类手滑而加的：只放**确定无疑**的几家，拿不准的服务商宁可不放也不预填错的模型名。
  选完模板后接口地址与清单里的模型**仍可随时增删、也可换当前**，改完即按自定义算（下拉自己翻回
  「自定义」，你的修改绝不会被模板覆盖回去）；模板**永远不碰** Key，也永远不回填已存档案的任何字段。
- **API Key 不进界面 DOM**（多档案时代的硬规矩，测试逐个档案钉住）：展开档案编辑时 Key 输入框
  **永远从空开始**——存储里的密钥不回填；**留空保存 = 保留原 Key**，填了才替换（当前版本
  没有"清空一个已存 Key"的界面动作，需要清 Key 时填个占位值再手工处理存储，属已知边界）。
  弹窗与设置页的任何文案、行、属性里都不会出现密钥（三个档案各塞不同密钥的断言在
  `tests/popup` 与 `tests/options`）；发给内容脚本的设置投影则**逐项剥掉**每个档案的
  `apiKey`（类型级投影，见「隐私」）。
- 接口地址的格式是 **Base URL**（代码会自动补 `/chat/completions`）。例如 OpenAI 用
  `https://api.openai.com/v1`，DeepSeek 用 `https://api.deepseek.com/v1`，Ollama 用
  `http://localhost:11434/v1`。设置值只接受 `https://`，本机回环地址（`localhost` / `127.0.0.1` / `::1`）
  额外放行 `http://`，其余地址会在设置页被当场拒绝（并说明原因），存储层也会拒绝这种值。
- **每个档案的接口地址要在设置页点一次该档案的「保存」才会申请访问授权**（Chrome 的可选
  宿主权限必须在用户手势里申请，只声明不申请等于永远没授权；申请按**那一个档案自己的** origin）。
  拒绝授权不影响保存：Key 与地址照常落盘，只是发往该地址的请求会被浏览器拦下，设置页会如实
  告诉你这一点。弹窗切到一个还没授权的档案时，提示区会明说"请到设置页保存一次该档案以授权"；
  真去翻译时报的也是这句可行动的 AUTH 错误，而不是伪装成断网的 `NETWORK`。删除**正在使用中**的
  档案时，`engineId` 明确切到**剩下的档案里第一个配好模型的**；一个都没有就置空，并在删除提示里
  直说「还没有可用的翻译引擎，去设置页添加一个服务商档案」——不会留下一个指向不存在档案的悬空选择。

### 翻译一直失败？先确认你的网络能不能到达你填的那个接口

**你填的那个接口可能在某些网络下到不了**（例如需要代理才能访问的境外服务），表现为请求既不
返回也不报错、直到超时。这时插件不是坏了，而是那个地址根本到不了——页面会提示「如果反复出现，
说明当前网络到不了这个翻译接口」，并让你在设置页核对那个档案的接口地址。

一分钟自查（在 PowerShell 里跑，把地址换成你想用的）：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" --max-time 8 "https://api.deepseek.com/v1/models"
```

- 打印出 `401` → **通**。401 只是"你没给 Key"，接口本身可达。
- 打印 `000` 或卡满 8 秒 → **不通**。换一个能到达的地址，或换一个服务商。

同理，`https://api.openai.com/v1` 在很多网络下也不可达。可用的替代：DeepSeek
（`https://api.deepseek.com/v1`，模型 `deepseek-chat`）、硅基流动、或本机跑的 Ollama
（`http://localhost:11434/v1`，无需 Key）。

## 验证

### 自动化：`npm run verify:dist`

`vite build` 退出码为 0 只说明打包器没报错，不代表产物能被 Chrome 加载——manifest 指向不存在的
文件、内容脚本里混进一条 ESM `import`、HTML 引用了一个没发射出来的资源，这三种都能让构建
「成功」而扩展直接报错或静默失效。`scripts/verify-dist.mjs` 把这些变成机器检查，逐项校验：

1. `dist/manifest.json` 存在、是合法 JSON、`JSON.parse` 通过；
2. `manifest_version === 3`；
3. manifest 引用的每个文件都真实存在（`background.service_worker`、`action.default_popup`、
   `options_page`、`content_scripts[].js` / `.css`、`icons` 等），一律**按 dist 根**解析；
4. `dist/content.js` 存在、非空、**不含 ESM 语法**（内容脚本以经典脚本注入，混入 `import` /
   `export` 会在加载时直接报语法错误）；
5. `dist/background.js` 存在、非空，且能在**语法层面**被解析（按 `manifest.background.type`
   选经典脚本或 ESM 解析器，只解析不执行）；
6. `dist/popup/popup.html` 与 `dist/options/options.html` 存在，且 HTML 里引用的本地 js/css
   都存在——Vite 会写成 `/popup.js` 这种**扩展根绝对路径**，脚本按 dist 根解析，
   不会误判成 `dist/popup/popup.js`；
7. `manifest.name` / `manifest.description` 是合法 UTF-8 中文（会被 PowerShell 5.1 的
   `Set-Content` 之类写成 GBK，读出来是乱码但「读得出来」，所以显式检查 U+FFFD 与 CJK）。

成功时打印一份**产物清单与每项大小**；失败时用非零退出码并逐条指出哪一项不满足。也可以单独跑：

```bash
npm run verify:dist
node scripts/verify-dist.mjs --dist some/other/dist   # 校验别的目录
```

**它不能替代什么**：扩展能不能真的加载进 Chrome、能不能真的翻译出一个网页，必须由人在浏览器里
操作。这正是下面这份清单存在的原因。

```
    有原链接颜色、可点击**的链接；多链接段落与正文小链接仍是纯文本黑字（预期边界，
    要点这种链接请还原或切双语）。
```

`npm test` 里有一条**规模基准**（`tests/content/extractor-scale.test.ts`）：它在一份 ≈8900 元素的合成页面上
采三遍取中位数，钉住元素数、段数（`segments=1175`，inline 载体修复的验收数字，形态 B 的卡片两段必须
采到）与样式查询复杂度（每次采集的样式读取 ≤ 元素数 ×1.2）。**它的绝对耗时上界默认不跑**——并发跑
多份 `vitest` 时 CPU 被抢，同一份页面能测出两倍的耗时（实测三份套件并发时它 2 红 1 绿，绿的那次只剩
1.3% 余量），而把阈值调到覆盖最差值等于把这道守卫废掉。要跑那条绝对上界就显式打开环境变量：

```powershell
$env:JY_SCALE_MS = '1'          # 只影响当前这个终端
npx vitest run tests/content/extractor-scale.test.ts
Remove-Item Env:\JY_SCALE_MS    # 关掉这一轮的开关
```

```bash
JY_SCALE_MS=1 npx vitest run tests/content/extractor-scale.test.ts
```

不开这个变量时，元素数、段数与样式查询复杂度三条断言照跑，只是不做绝对耗时判断。

发布打包：`npm run zip`（`scripts/zip-dist.mjs`，只用 Node 标准库、零依赖）读取
`dist/manifest.json` 的 version 产出仓库根目录的 `translens-<version>.zip`（Chrome 商店/侧载
上传用的就是它）。它**有意不接进 `npm run build`**（构建保持纯净，想发才打）。打完立即
自检：用自带读取器解回临时目录，比对文件数、逐文件字节内容、每条目 CRC-32 与中央目录布局，
条目名一律 `/` 分隔（Windows 反斜杠会让 Chrome 加载失败）；自检不过会删掉产物并以非零退出——
**打不出可用 zip 的打包脚本等于没有**。`dist/` 不存在时直接报错提示先 build，不会静默产出
空包。`node scripts/zip-dist.mjs --check <zip> --dist <dir>` 可单独跑这份校验。

开发时的循环：两个 `dev:*` 各占一个终端 → 改代码 → 回到 `chrome://extensions` 点该扩展的
**刷新**按钮 → 刷新目标网页（内容脚本变更必须刷新网页才生效）。

## 隐私

- **API Key 只存在本机 `chrome.storage.local`**（每个服务商档案自带一份 Key），不上传、不同步、
  不写入日志，也不会进入发给内容脚本的设置投影（内容脚本跑在网页进程里，拿到的设置里
  **每个档案都没有** `apiKey` 字段——列表投影是逐项剥离，不是剥一个顶层字段）。设置页的档案
  编辑框同样**不回填**密钥：Key 输入框永远从空开始，留空保存即保留原 Key，任何档案的任何密钥
  都不会渲染进页面 DOM。
- **设置页的即时保存会多写一点本地存储**：每次改动重读 + 整份写回设置；另外在
  `chrome.storage.session` 里留一条档案测试记录（键 `jinyi:engine-health`：哪个档案、通没通、
  失败原因）。它不含 API Key，也不含任何页面内容，浏览器关闭即清空。
- **除翻译请求本身外，不发起任何网络请求**，不采集任何浏览数据、不做统计上报。
- **译文一律以纯文本写入页面**（`textContent`），不执行任何来自接口的 HTML 或脚本；译文宿主是
  带 Shadow DOM 的自定义元素，不会把接口返回的内容当成 HTML 解析。
- 页面权限按最小化申请：**不声明任何默认主机权限**（`host_permissions` 是空的 `[]`）——
  安装与更新都不会请求任何站点访问权。自定义端点走 `optional_host_permissions`，
  并且**只在你点设置页「保存」时**按你填的那个
  origin 申请（已经授权过就不再弹框）。没授权时翻译会明确告诉你「未授权访问该接口地址」，
  而不是把浏览器的拦截伪装成断网。
- **另外声明了 `activeTab`**：它只在**你点击扩展图标打开弹窗**时，授予**当前那个标签页**的
  临时访问权（弹窗要靠它读到当前标签页的地址，才能知道这一站有没有被规则设为「永不翻译」）。
  它**不产生任何安装警告**——`tabs` 权限才会产生"读取您的浏览记录"那条，为一个状态行不值得，
  所以有意选了 `activeTab`。**边界说清楚**：`activeTab` 管的是**弹窗那条链**（`Tab.url` 可读）；
  内容脚本本来就是按 `content_scripts.matches` 在 http/https 页面上注入并运行的，与这项权限
  无关——它跑在页面里，读的是页面自己的地址。
- 只有在网页里**可见**的文本才会被送去翻译：`display:none`、`aria-hidden="true"` 里的内容
  （未发布草稿、折叠面板、A/B 变体）不采集；`<script>`、`<style>`、`<code>`、`<pre>`、
  表单**控件的值**（`<input>` / `<select>` / `<textarea>` / `<option>`，不是页面正文）与
  `<svg>` / `<canvas>` / `<iframe>` 等也一律跳过。**按钮上显示的文字属于界面正文，照常
  翻译**（`<button>` 不在跳过名单里）；纯图标的按钮（`×`、`☰`、`3`）由噪声闸
  （至少两个字母）挡下，不送接口。
- **悬停与划词只响应真实用户手势**：页面脚本派发的事件（`isTrusted: false` 的 mouseup /
  keydown / mouseover）一律不触发翻译——否则任何页面都能自设选区再合成一个 mouseup，把扩展
  当成"带着你的 Key 烧你额度"的翻译代理。右键菜单那条路径由浏览器自己的菜单点击驱动，
  本身就是用户手势，不经这道闸门。
- **可编辑区域（`contenteditable`）内的文本不会被翻译**：用户正在写、还没保存的内容
  （邮件草稿、笔记、评论框）属于隐私——它是用户的半成品，不是网页的内容。可编辑性会
  继承给后代，所以整个可编辑子树一个字符都不采集；**整页采集与划词共用同一份判定**——
  划词选区的锚点与焦点任一端落在可编辑子树内，这一次划词就不送出去。所见即所得编辑器用
  `contenteditable="false"` 嵌进去的只读片段不算草稿，照常翻译。

## 已知限制

以下都是**这一版真实存在**的行为，不是"以后可能会有的优化"：

### 站点规则

- **站点规则只拦整页翻译**（右键菜单 / `Alt+T` / 弹窗按钮）。**划词与悬停翻译不受约束**——
  那是你主动发起的单段翻译，与"这个站整页不该翻"是两件事。
- 规则只认两种写法：`example.com`（精确，不含子域）与 `*.example.com`（含裸域与任意层子域）。
  自上而下首条命中即生效。**其余写法（`*example.com`、`https://example.com`、`example.com:8080`）
  不报错、只会永不命中**；规则按 punycode/ASCII 匹配，填中文域名会静默失效。
- `action: 'translate'`（总是翻译）目前**没有可观察行为**，因为本扩展还没有自动翻译功能；
  设置页暂不提供这个动作，等自动翻译落地再补。
- 弹窗里的「此站已设为永不翻译 · 解除」依赖 `activeTab` 权限读取当前标签页地址。
  **这条链路目前只有文档依据、未在真机验证过**（本机没有浏览器）。若你在弹窗里看不到那行，
  请先确认扩展已重新加载。
- **规则的闸只装在整页翻译的入口上**（内容脚本的 `translatePage()`）。这意味着：页面**已经翻译之后**
  再加规则，**已经翻好的内容与之后新出现的内容都不会被撤掉**——增量链路（`MutationObserver`）
  不受站点规则约束。单元 A 落地时这条缝实际不可达（当时只能删规则），**设置页有了写入侧之后它就真的可读了**。
  要立刻生效：先按 `Alt+T` 还原，再重新翻译。设置页的站点规则区块里也写着这一条。

### 设置页

- **视觉基线是 Apple 风格表皮（单元 D）**：配色/圆角/控件语言取自 `docs/mockups/options-apple.html`，
  字体用系统栈、**不打包**（Windows 实际落到 Segoe UI/微软雅黑）；不做毛玻璃、不改 DOM 结构。
  观感与明暗两版同样**未经真实渲染验证**（本机没有浏览器），由用户肉眼验收。
- **即时保存的语义**：改一个字段 → 重读一次存储 → 只改这一个字段 → 整份写回。写失败（存储里是
  更高版本、读写失败）会把控件拨回真正生效的那一档，并在该区块的状态行里说明原因。
- **代价（如实）**：同一个扩展同时打开两个设置页时，后写的一方会覆盖前一方。这与改版前"点保存即覆盖"
  是同一性质，本轮不解决。另外写入频率从"每次点按钮"提高到"每次改动"，量级很小（设置页不是高频界面），
  但没有实测。
- **状态点只在本次浏览器会话内有效**：绿/灰/红记在 `chrome.storage.session`（键 `jinyi:engine-health`，
  内容只有各档案的记录键（`p:` + 档案 id）与成败原因，不含 Key、不含页面内容）。浏览器关闭后记录清空，所有点回到灰
  （"从没测过"）——重新测一次即可。
- **窄窗口（< 900px）下左导航降级为顶部一行可横滚的胶囊链接**（不再吸顶，分组标题隐藏）。
  **这条降级策略没有在任何真实渲染里验证过**（本机没有浏览器），布局挤压与暗色对比度同样依赖肉眼验收。
- 术语表的空行（原文或译文为空）不会写进存储；**把已经有的一行清空也不会静默删掉它**——界面会明说
  「没有保存；存储里仍是原来那条」，要删请点行尾的「删除」。站点规则的域名同理。
  （理由：清空多半是"清掉重打"，在失焦那一刻删条目会让正在编辑的一行当场消失，而这份界面没有撤销出口。）
- **在文本类控件里按 `Esc` 不会撤销这次改动**：多数浏览器在改动后仍然会派发 `change`，于是那次改动
  照常落盘。改版前有「保存」按钮时可以反悔，现在没有这个出口——要改回去就再改一次，列表行则用行尾
  「删除」。本轮不实现"Esc 撤销"：本机没有浏览器可以验证 `Esc` 在各控件上的真实语义，凭猜测写一个
  半可用的撤销比不写更糟。
- **面板里没保存的改动会被记住**（只要你还在这张设置页上）：点另一个档案的「编辑」看一眼再点回来、
  或把本行收起再展开，名字 / 接口地址 / Key / 模型清单都还是你刚填的样子——每个档案在内存里各留一格
  暂存。**「取消」才是丢弃**（它会把那格一起清掉）。这不是自动保存：**关掉设置页暂存就没了**，
  也永远不会把半填的档案悄悄写进存储——要落盘只能点「保存」。
- **展开档案行变快，只有 jsdom 这一层的读数**：改前每点一次展开都会把整张档案列表推倒重建
  （代价随档案数线性增长），改后只动受影响的那一两行——测试钉住的是"单次展开对 DOM 的改动量与
  档案数无关"（N=5/20/50 同值），**不是真机耗时**（本机没有浏览器，绝对耗时测不了）。若你复测仍慢，
  下一步是加一个临时的 `console` 计时探针定位到底是哪一段慢。
- **模型清单没有条数上限，也没有搜索框**：有些网关的 `/models` 列几百个，勾选清单只做"可滚动 +
  勾选"；手填只校验"非空 + 不重复"，**不校验服务商认不认识这个名字**——填错会在翻译时拿到服务商
  自己的 400（错误码 `BAD_REQUEST`，正文原因会展开显示）。
- **「自定义」徽章的判据是"接口地址与某个内置模板逐字相同"**：地址是自己搭的代理、或者多打了一个
  斜杠，徽章就会出现（这是有意的：判据越"聪明"，你越难预测它什么时候亮）。
- **模型那一行在 0 / 1 个模型时"不占位"这件事，测试侧零覆盖**：它靠 `popup.css` 的
  `.field[hidden] { display: none }`（`.field` 是 flex，会盖掉浏览器默认的 `[hidden]`）——
  jsdom 没有布局、`popup.test.ts` 也不加载 `popup.css`，把那条规则整条删掉**测试仍然全绿**。
  所以**请你在真机上确认**：切到一个只有 0 或 1 个模型的档案时，那行不该留一条空白。
- **折叠行比参考图多一行小字**（`接口地址 · 当前模型`）：这是有意的——5 个档案时"哪个档案打哪个
  地址、用哪个模型"是一眼就该看见的信息。窄窗口下这一行可能被挤窄，**未经真机渲染验证**。
- **点整行（含名字文字）不再展开**：折叠行右侧那个「编辑」按钮才是展开开关（展开后文案变「收起」），
  它旁边还有「删除」——整行可点会把"删除"变成一次误触。所以在折叠行上点名字本身没有任何反应，
  要展开请点「编辑」（`src/options/sections/engine.ts` 的 `buildProfileRow`：行头已经不是一个按钮）。
- **`/models` 只在点「⟳ 获取可用模型」那一下才发请求**：打开设置页、切到别的档案、把光标点进接口
  地址输入框，都**不会**自动拉取。拉回来的清单是服务商原样给的，插件**不校验**你能不能调用其中
  每一个——有些网关的 `/models` 返回的是**全部**模型（含你没开通的），所以勾选并入之后仍然可以
  手填、也可以逐个删除来修正。清单里一条都认不出来时按"这个地址没有给出可用的模型清单——不是
  所有服务商都实现了它"处理并引导手填（`src/background/models.ts` 的 `fetchModels` 此时返回的是
  **成功 + 空清单**，不是网络失败；设置页照常把这句如实显示出来）。
- **没有「当前」模型时给的是一句可行动的错误**：这个档案还没有模型，点「添加模型」或「拉取可用
  模型」——**而且一个请求都不发**。零请求不是"某道闸"的功劳：`src/engines/openai-compat.ts` 在
  发 `fetch` 之前就因为模型名为空抛了 AUTH，任何调用方都发不出去。
- **设置版本只向前（v3 → v4 → v5），降级不做**：
  - v3 → v4：每个档案的单个 `model` 在**读取时**被抬起成 `models: [model]` + `activeModel: model`
    （空 / 缺失 → 空清单 + 空当前项）；
  - v4 → v5：`engineId` 是免费接口的，改指向**第一个有当前模型的档案**（一个都没有就置空）；
  - 两者都发生在**读取时**，落盘要等用户下一次改动（写回时版本号写成当前版本）。
  **降级方向没有兼容**：装了新版再回退到旧版扩展时，旧代码的版本闸门会直接报错
  「设置版本 N 高于当前支持的 M，请更新扩展」——旧版是**明确读不出来**，而不是把模型显示成空。

### 功能范围

- **显示模式、悬停翻译、划词翻译都已接到内容脚本**：`displayMode` 默认「仅译文」；
  `hoverTranslate` / `selectionTranslate` 有弹窗与设置页两处开关并即时生效。**增量翻译已实现**
  （见上文「增量翻译」：仅新增内容，防抖 500ms，单轮上限 60 段；另有"用户交互后整页重扫"
  这条兜底，防抖 400ms、节流 1 秒、元素数超过 15000 时跳过）。
- **设置页有 8 个区块**（左导航分「翻译 / 内容控制 / 数据」三段）：翻译引擎、语言与显示、
  快捷翻译、术语表、站点规则、自定义提示词、缓存与请求、隐私。其中**源语言、术语表、站点规则的写入侧、
  自定义提示词、并发与批量**是 2026-09 这一轮新露出的界面——它们背后的字段本来就有真实消费者
  （`sourceLang` 进请求与缓存 key；`glossary` / `systemPrompt` 进 `buildMessages` 与缓存 key；
  `concurrency` / `maxBatchChars` / `maxSegmentsPerBatch` 被内容脚本与 `core/segmenter` 读；
  `siteRules` 的匹配与拦截见上文「已知限制 › 站点规则」）。
- **设置改动即时保存**：选择类与开关类 `change` 即存，文本类（术语、规则域名、提示词）失焦才存，
  数字类在提交时存。**档案仍用面板底部的「保存」按钮**——保存档案要在用户手势里申请该地址的宿主权限
  （Chrome 要求手势），而且填了一半的档案不该被静默写进存储。同一个面板上的「取消」丢弃这次编辑、
  不动存储（收起 / 切走**不会**丢弃——见上面「面板里没保存的改动会被记住」那条）。
- **弹窗里那个模型下拉只在清单有 2 个以上模型时出现**（0 个 / 1 个都不显示——一个只有一项的下拉是
  噪声）。**换模型不会自动重翻当前页面**：弹窗会明说「换模型后需重新翻译（`Alt+T`）才会用新模型」。
  缓存 key 里含 `model`，所以重新翻译不会命中旧模型的译文（`src/background/scheduler.ts` 的
  `configHash` 由 `baseUrl` + `model` 组成）。
- **删除已存档案的"Key 输入框留空 = 保留原 Key"没有反向操作界面**：想把某个档案的 Key
  清空，当前只能填个占位值或到 `chrome.storage.local` 里手工改。属已知边界，无隐私风险。
- **悬停/划词的段落与选区只读页面文本，不读可编辑区域与插件自己的浮层**：编辑框草稿、
  气泡内文字被划中都不会送接口。悬停段落判据与整页翻译共用 `extractor` 的一份实现。
- **「仅译文」模式下，整页翻译进行中时悬停暂时不可用**（划词不受影响）。原因是仅译文模式会把
  原文整体搬进隐藏容器，而悬停的段落判据必须跳过插件自己的节点——否则会去翻译已经藏起来的文本。
  整页翻译跑完或按 `Alt+T` 还原后，悬停立即恢复。双语模式没有这个窗口。
- **`autoTranslateDelay`（自动翻译延时）既没有界面，也没有任何行为**：全仓没有任何代码读它
  来触发自动翻译——自动翻译这个功能本身尚未实现，在存储里把这个数设成多少都不会有
  任何效果。（别把它和上面那批字段混为一谈：上面那批背后有真实消费者、2026-09 这一轮刚露出界面，
  改了确实生效；它连这一轮都没进——因为它连行为都没有，改了什么都不发生。）

### 段落识别与采集

- **「inline 包块级」的载体现在会被正常下钻（digitalocean mega-menu 卡片事故的修复）。**
  块级边界的判据是「这个元素里有没有需要独立成段的块级内容」，不是「这个元素自己的 display」：
  除块级 display 外，**一切**非 `none` 的 display（含纯 `inline`、`inline-block`、`contents`、
  未知值）都会探查内部有没有块级后代。旧判据只对 4 种"透明 display"探查，纯 `inline` 被漏掉，
  而「整张卡片包在 `<a>` 里」（`<a>` 默认 inline）是最常见的卡片写法——那种子树既不成段也不参与
  拼接，**整片区域静默没有译文**（2026-09 修）。
- **已知限制（实测的临界值）：连续超过 16 层的纯行内包裹仍会漏翻。**
  块级后代探查有递归深度上限 `MAX_WRAPPER_DEPTH = 16`（防病态深树吃栈，刻意不调大——那是拿
  调用栈换正确性）。实测：`<a>` 与块级内容之间垫 **16 层**行内包裹照常采到，**17 层起整段丢失**
  （`tests/content/extractor-inline-carrier.test.ts` 把这两个数钉在用例里）。真实触发形态是
  styled-components 一类"逐层行内 wrapper"叠出超长纯行内链；常规卡片（`a > div > …`）远在上限内。
  漏掉时诊断不再给假希望：结论是「未采集：采集端下钻不到这里」，点名断点的 tag/类与 display。
- **代价有实测数字（jsdom，8875 元素合成页）**：修复前后单次整页采集耗时中位数
  1666ms → 2030ms（**×1.22**，其中还包含把原先静默丢的 150 段真的采出来的工作量；
  无事故形态的页面约 ×1.13）。样式查询次数保持线性（每元素至多一次，探查走同一份缓存）。
  基准与阈值钉在 `tests/content/extractor-scale.test.ts`（**那条绝对耗时上界现在要 `JY_SCALE_MS=1`
  才跑**，默认跑的是元素数、段数与样式查询复杂度三条，见「开发」）。未加 memo 是刻意的：多付的是
  树遍历而不是样式解析，1.2 倍量级不值得再引入一层会跨采集失效失真的缓存。

### 语言判定

- **纯汉字、不含假名的日文段落（如「東京都港区赤坂」）不再被静默跳过。** 单段层面分不出
  "中文"与"只用汉字的日文"，但"这页像不像日文"是整页就能看出来的信息：整页出现过假名/片假名时，
  本轮采集不再因"看起来已是目标语言"跳过这类段落。实现是内容脚本在采集前对整页文本做**一次**
  廉价假名扫描（`core/lang.ts` 的 `containsKana` 保持纯函数，页面状态留在内容脚本侧，
  `shouldSkip` 只多收一个 `allowSameScriptSkip` 选项），判定缓存供本轮整页采集与之后所有
  增量轮复用（不每段扫、也不每轮重扫）。方向上只会**多翻**不会少翻；页面不含假名时行为与过去
  逐字相同（中文页面翻中文仍然整体跳过、零请求）。残留代价如实写：真·中文内容恰好出现在
  含假名页面上（少见）会被多送一遍翻译；页面正文一处假名都没有、纯靠汉字书写的日文段落，
  在不含假名的页面上仍然无法识别——那种场景没有任何可用信号。
- 语言判定按**字符集**（中文 / 日文 / 韩文 / 俄文 / 阿拉伯文 / 拉丁）分档，只在目标字符集
  **严格领先**时才跳过；分数持平（例如极短的混排 `Hi 你好`）一律照常翻译——宁可多翻一遍，
  也不要静默漏翻。

### 渲染

- **仅译文模式下，"几乎整段就是一个链接"的段落会保留可点链接；其余段落的链接仍点不了。**
  当一段原文里**恰好只有一个**可见的 `<a href>`、且链接文本占整段文本 **≥60%**（作者署名行
  "By Davide Castelvecchi"、整标题链接这类形状），译文会被渲染成链接：仍可点击，颜色与
  下划线从原链接的样式抄来（译文在 Shadow DOM 里，页面 CSS 进不来，只能抄）。href 只认
  `http:` / `https:` / `mailto:` 白名单——`javascript:`、`data:`、相对协议等一律不带入译文，
  该段直接按纯文本处理。**边界如实说**：含**多个链接**的段落（译文整体该指向哪个链接没有
  答案）与链接**占比不足**的正文段落（包起来等于把整段涂蓝）仍是纯文本、仍点不了，
  需要点这样的链接时按 `Alt+T` 还原，或在弹窗里切「双语对照」后重新翻译。
- **仅译文模式只对"整段元素"生效到底。** 段落是 `<p>` / `<li>` / `<td>` 这类最内层文本块时，
  整块**承载文字的**原文都会被藏起来；而容器里**夹在块级子元素之间的直接文本**（`<div>Intro<p>Body</p></div>`
  里的 Intro）只能藏它自己那一串——整块藏掉会把兄弟段落连同它们的译文一起藏没。
  遇到结构判不准的情况宁可少藏（那一小段仍是原文）也不会多藏，不存在"内容凭空消失"。
- **按钮上的文字会被翻译。** `<button><span>Products</span><svg>箭头</svg></button>`
  这类形态（digitalocean 顶部导航的 Products / Solutions / Developers / Partners 之前完全没被翻译，
  因为 `<button>` 在跳过名单里、而跳过是整棵子树级别的）现在双语与仅译文两种模式都会翻。
  表单控件的**值**（输入框、下拉、文本域）仍然不翻，那不是页面正文。
- **仅译文模式下图标尽量保留，但两种情况保不住**（如实写，不要当成普遍保证）：
  规则是只搬走**承载文字**的节点，`<svg>`、`<img>`、空图标 `<i>`（CSS 画的）、纯空白
  这类纯视觉节点留在原位保持可见，译文宿主紧跟隐藏容器插入，所以箭头图标仍排在译文
  「产品」之后。被文字节点夹在中间的留底节点会把隐藏容器断成多串，每串各自一个容器，
  还原依旧逐字节回到原样。但：
  - **按钮自己不是段落时保不住图标**。若按钮是行内盒、它的文字被并进**祖先容器**那一段里，
    整个 `<button>`（连同里面的 svg）会被当作"一个承载文字的节点"搬走，图标跟着消失。
    按钮自己被块级化/flex 化的形态（真实站点导航的常见写法）不受影响。
  - **字体图标保不住**。用私有区字符画图标的那种（`<i class="fa"></i>`）里的字符是
    非空白文本节点，按"承载文字"处理会被搬走，图标消失，且那个字形字符会随文本送进接口
    （涉及的码位是 U+E000–U+F8FF 私有区，Font Awesome 等 icon font 的常见用法）。
    只有靠 CSS `::before` 画的空 `<i>` 会留在原位。
- **翻译失败时该段原文会重新显示出来**：仅译文模式下，失败位置在标注红色错误文案与
  「重试」按钮（缺 API Key 这类重试多少次都一样的错误只显示原因、不挂按钮）的同时，会把
  这一段的原文放回可见——整页都失败时，页面读起来仍是原文加上逐段错误标注，而不是把内容
  整个拿走只剩一片红字。点「重试」或重新翻译时原文再藏回去，成功译文照常顶上；
  按 `Alt+T` 也随时可以完全还原。
- 表格用单元格级译文，但**复杂布局（`position: absolute` 的浮层、跨行跨列的复杂表头、
  画布内文字）不做特殊适配**——译文可能位置不佳，请用 `Alt+T` 还原。
- 页面结构在翻译过程中被前端框架重建时，译文宿主可能被一并移除；**增量层只处理新增子树**
  （新节点会翻），但「已有节点被改动/移除」不在重译范围内——见上文「增量翻译」的最后一条，
  这类页面还原重译一次即可。
- **文档元素超过 15000 个的页面上，不做"用户交互后的整页重扫"**（见上文「增量翻译」）：
  这类页面上那种"展开时不留下任何可观察痕迹"的内容（portal 现渲染的下拉菜单等）翻不出来，
  需要还原重译一次。这是刻意的取舍——把几百毫秒的整页采集挂在每一次点击后面更糟。

### 其他

- 单页面翻译期间弹窗主按钮会置灰，超过 30 秒仍未完成时弹窗会提示"重新打开弹窗查看进度"——
  这是**预期行为**，几百段的页面本来就会超过这个时限。
- **把标签页切到后台，翻译会明显变慢**（这是浏览器的行为，不是本扩展的缺陷）：实测标签页
  隐藏约 90 秒后，Chrome 会把该页面的定时器节流到**每分钟只醒一次**，于是每一批的收尾都要
  多等最多 60 秒。台架实测（215 段、把单批延迟固定成 45 秒以放大效应）：这批的前台理论值是
  270 秒（18 批 ÷ 并发 3 × 45 秒），切后台实测 360 秒才翻完。
  **想让翻译快，就保持那个标签页在前台可见**（不用一直盯着，只要别切走）。
  页面在此期间始终显示「翻译中…」，看起来像卡住，其实是在按分钟推进。
- 翻译结果缓存在 `chrome.storage`（会话级 + 持久级两层），缓存内容包含原文与译文；
  它不包含 API Key。
