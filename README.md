# 浸译（JinYi）

沉浸式网页翻译扩展：**保留原文，在每一段下方就地插入译文**——读的时候是双语对照，随时可以一键还原。

- Manifest V3，Chrome / Edge 可用。
- 默认使用免费的 Google 翻译接口，装好即用，零配置。
- 译文以纯文本写入页面的 Shadow DOM，不影响原页面样式。

---

## 安装

```bash
npm install
npm run build
```

然后在 Chrome 里加载：

1. 打开 `chrome://extensions`
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选择本仓库的 **`dist` 目录**（注意是 `dist`，不是仓库根目录）

加载成功后工具栏会出现「浸译」图标。`dist/` 只在 `npm run build` 之后才存在，且已被 `.gitignore` 忽略。

> `npm run build` 的最后一步会自动运行 `npm run verify:dist`（见下文「验证」），
> 它不通过时构建会以非零退出码失败——所以 **「构建成功」就等于「产物可加载」**。

---

## 使用

| 操作 | 效果 |
| --- | --- |
| `Alt+T`（可点 `chrome://extensions/shortcuts` 改键） | 翻译当前页面；再按一次完全还原 |
| 点击工具栏图标 | 打开弹窗：翻译此页 / 显示原文、切换**目标语言**、切换**翻译引擎** |
| 弹窗右上角 ⚙ | 打开**设置页**：接口地址 / API Key / 模型名、目标语言、清除翻译缓存、测试连接 |
| 右键菜单 · **翻译此页** | 翻译当前页面 |
| 右键菜单 · **翻译选中文本** | 预留入口，当前版本不弹气泡（见「已知限制」） |

工具栏图标上如果没有看到图标，点拼图按钮把「浸译」固定到工具栏即可。

## 翻译引擎

| 引擎 | 需要 Key | 说明 |
| --- | --- | --- |
| **Google 免费接口**（默认） | 否 | 走 `translate.googleapis.com`，零配置可用 |
| **OpenAI 兼容 API** | 是 | 走 `{接口地址}/chat/completions`，可接 OpenAI、DeepSeek、硅基流动、Ollama 等 |

引擎可以在**弹窗**里切换（「翻译引擎」下拉，改完立即写入本机存储）。

### 当前版本的真实限制

- **免费接口不稳定、可能被限流。** 它是非官方接口，没有 SLA；触发限流时页面会提示
  「免费接口限流，请稍后重试或改用自定义 API」，并给出重试按钮。免费接口也**不支持术语表**
  （`supportsGlossary: false`）。
- 自定义引擎的接口地址、API Key、模型名在**设置页**里填（弹窗右上角 ⚙）。设置页有
  「测试连接」按钮：它会用你当前填的内容真的翻一次 `hello`，成功显示译文、失败显示错误码。
- 接口地址的格式是 **Base URL**（代码会自动补 `/chat/completions`）。例如 OpenAI 用
  `https://api.openai.com/v1`，DeepSeek 用 `https://api.deepseek.com/v1`，Ollama 用
  `http://localhost:11434/v1`。设置值只接受 `https://`，本机回环地址（`localhost` / `127.0.0.1` / `::1`）
  额外放行 `http://`，其余地址会在设置页被当场拒绝（并说明原因），存储层也会拒绝这种值。
- **自定义接口地址的访问权限要在设置页点一次「保存」才会申请**（Chrome 的可选宿主权限
  必须在用户手势里申请，只声明不申请等于永远没授权）。拒绝授权不影响保存：Key 与地址照常
  落盘，只是发往该地址的请求会被浏览器拦下，设置页会如实告诉你这一点。

### 翻译一直失败？先确认你的网络能不能到达接口

**默认的免费 Google 接口在很多网络下（例如中国大陆）被完全阻断**，表现为请求既不返回也不
报错、直到超时。这时插件不是坏了，而是那个接口根本到不了——页面会提示「如果反复出现，说明
当前网络到不了这个翻译接口」，并告诉你去设置页换一个。

一分钟自查（在 PowerShell 里跑，把地址换成你想用的）：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" --max-time 8 "https://api.deepseek.com/v1/models"
```

- 打印出 `401` → **通**。401 只是"你没给 Key"，接口本身可达。
- 打印 `000` 或卡满 8 秒 → **不通**。换一个能到达的地址，或换一个服务商。

同理，`https://api.openai.com/v1` 在很多网络下也不可达。可用的替代：DeepSeek
（`https://api.deepseek.com/v1`，模型 `deepseek-chat`）、硅基流动、或本机跑的 Ollama
（`http://localhost:11434/v1`，无需 Key）。

## 验证

### 自动化：`npm run verify:dist`

`vite build` 退出码为 0 只说明打包器没报错，不代表产物能被 Chrome 加载——manifest 指向不存在的
文件、内容脚本里混进一条 ESM `import`、HTML 引用了一个没发射出来的资源，这三种都能让构建
「成功」而扩展直接报错或静默失效。`scripts/verify-dist.mjs` 把这些变成机器检查，逐项校验：

1. `dist/manifest.json` 存在、是合法 JSON、`JSON.parse` 通过；
2. `manifest_version === 3`；
3. manifest 引用的每个文件都真实存在（`background.service_worker`、`action.default_popup`、
   `options_page`、`content_scripts[].js` / `.css`、`icons` 等），一律**按 dist 根**解析；
4. `dist/content.js` 存在、非空、**不含 ESM 语法**（内容脚本以经典脚本注入，混入 `import` /
   `export` 会在加载时直接报语法错误）；
5. `dist/background.js` 存在、非空，且能在**语法层面**被解析（按 `manifest.background.type`
   选经典脚本或 ESM 解析器，只解析不执行）；
6. `dist/popup/popup.html` 与 `dist/options/options.html` 存在，且 HTML 里引用的本地 js/css
   都存在——Vite 会写成 `/popup.js` 这种**扩展根绝对路径**，脚本按 dist 根解析，
   不会误判成 `dist/popup/popup.js`；
7. `manifest.name` / `manifest.description` 是合法 UTF-8 中文（会被 PowerShell 5.1 的
   `Set-Content` 之类写成 GBK，读出来是乱码但「读得出来」，所以显式检查 U+FFFD 与 CJK）。

成功时打印一份**产物清单与每项大小**；失败时用非零退出码并逐条指出哪一项不满足。也可以单独跑：

```bash
npm run verify:dist
node scripts/verify-dist.mjs --dist some/other/dist   # 校验别的目录
```

**它不能替代什么**：扩展能不能真的加载进 Chrome、能不能真的翻译出一个网页，必须由人在浏览器里
操作。这正是下面这份清单存在的原因。

### 手动验收清单（需要真人在 Chrome 里操作）

> 说明：第 6、7 条依赖「设置页填 Key / 模型」这条路径，设置页已经可用（见「使用」），
> 所以整份清单现在都可以逐条走。

```
1. 打开一篇维基百科英文长条目 → 按 Alt+T → 正文各段落下方出现译文；再按 Alt+T → 页面完全还原。
2. 打开 Medium 上任意一篇长文（弹性布局为主）→ 翻译 → 译文换行显示在原文下方，没有被挤到同一行。
3. 打开 MDN 上任一含表格的文档页 → 翻译 → 表格单元格译文留在单元格内，表格结构未错位。
4. 打开 X/Twitter 或任一 SPA 站点 → 翻译 → 页面不卡死、不报错。
5. 断网 → 翻译一个页面 → 译文位置显示红色失败提示与「重试」按钮；恢复网络后点重试 → 该段出现译文。
6. 设置页把引擎切到 OpenAI 兼容但不填 Key → 弹窗显示警告 → 翻译页面 → 提示需要填 Key。
7. 填入可用的 Key 与模型 → 点「测试连接」应显示译文 → 翻译同一页面 → 译文正确、段落数与原文一致。
8. 还原后重新翻译同一页面 → 除页面自身请求外不应出现新的翻译请求（全部命中缓存）。
9. 打开一个中文页面 → 翻译 → 提示没有找到需要翻译的内容，不发翻译请求。
10. 右键菜单：页面空白处右键「翻译此页」生效；选中文字右键「翻译选中文本」不报错。
```

## 开发

```bash
npm install

npm test              # 单元测试（vitest，当前 368 个用例）
npm run typecheck     # 类型检查（tsc --noEmit）
npm run build         # 类型检查 → 打包 → verify:dist

npm run dev:main      # 监听重建 background / popup / options（另开一个终端）
npm run dev:content   # 监听重建内容脚本（另开一个终端）
```

开发时的循环：两个 `dev:*` 各占一个终端 → 改代码 → 回到 `chrome://extensions` 点该扩展的
**刷新**按钮 → 刷新目标网页（内容脚本变更必须刷新网页才生效）。

目录结构：

```
src/
  manifest.json          静态 manifest，构建时原样发射到 dist/
  background/            service worker：消息路由、右键菜单、快捷键、缓存与调度
  content/               内容脚本：段落采集、渲染、还原（构建为经典脚本 content.js）
  core/                  纯函数层：语言判定、分段、缓存、并发池
  engines/               翻译引擎适配器（Google 免费接口 / OpenAI 兼容）
  popup/                 工具栏弹窗
  options/               设置页：引擎配置（含测试连接）、目标语言、清缓存、隐私说明
  shared/                设置读写、消息协议、可选宿主权限
scripts/
  verify-dist.mjs        产物可用性校验（npm run verify:dist）
tests/                   vitest 用例
```

## 隐私

- **API Key 只存在本机 `chrome.storage.local`**，不上传、不同步、不写入日志，也不会进入发给
  内容脚本的设置投影（内容脚本跑在网页进程里，拿到的设置里根本没有 `apiKey` 字段）。
- **除翻译请求本身外，不发起任何网络请求**，不采集任何浏览数据、不做统计上报。
- **译文一律以纯文本写入页面**（`textContent`），不执行任何来自接口的 HTML 或脚本；译文宿主是
  带 Shadow DOM 的自定义元素，不会把接口返回的内容当成 HTML 解析。
- 页面权限按最小化申请：默认只声明免费引擎域名（`https://translate.googleapis.com/*`）；
  自定义端点走 `optional_host_permissions`，并且**只在你点设置页「保存」时**按你填的那个
  origin 申请（已经授权过就不再弹框）。没授权时翻译会明确告诉你「未授权访问该接口地址」，
  而不是把浏览器的拦截伪装成断网。
- 只有在网页里**可见**的文本才会被送去翻译：`display:none`、`aria-hidden="true"` 里的内容
  （未发布草稿、折叠面板、A/B 变体）不采集；`<script>`、`<style>`、`<code>`、`<pre>`、
  表单控件与 `<svg>` / `<canvas>` / `<iframe>` 等也一律跳过。
- **可编辑区域（`contenteditable`）内的文本不会被翻译**：用户正在写、还没保存的内容
  （邮件草稿、笔记、评论框）属于隐私——它是用户的半成品，不是网页的内容。可编辑性会
  继承给后代，所以整个可编辑子树一个字符都不采集；所见即所得编辑器用
  `contenteditable="false"` 嵌进去的只读片段不算草稿，照常翻译。

## 已知限制

以下都是**这一版真实存在**的行为，不是"以后可能会有的优化"：

### 功能范围

- **当前版本只实现「整页双语对照」。** 以下均**尚未实现**（属下一阶段）：
  整页替换、悬停翻译、划词气泡、增量翻译、站点规则、术语表编辑界面。
  设置里虽然已有 `displayMode` / `hoverTranslate` / `selectionTranslate` / `siteRules` /
  `glossary` 等字段并能持久化，但**没有对应的界面，也没有接到内容脚本上**；`displayMode`
  当前恒为 `bilingual`。
- **设置页只做了最必要的那几项**：引擎配置（接口地址 / API Key / 模型名 / 测试连接）、
  目标语言、清除翻译缓存、隐私说明。站点规则、术语表、提示词、并发与批大小等高级项
  **仍然没有界面**（字段能持久化，但只能在存储里改）。
- **右键「翻译选中文本」不弹气泡**：内容脚本有意不处理这条消息（Plan 2 的接口预留），
  它不会报错，但也不会有任何可见效果。
- 翻译**语言方向固定为「自动检测源语言 → 目标语言」**（`sourceLang` 已进缓存 key，
  但设置页还没有选源语言的控件）。

### 语言判定

- **纯汉字且不含假名的日文（如「東京都港区赤坂」）会被判为中文，目标为中文时会被跳过。**
  汉字是简繁日共用的书写系统，单段文本层面没有任何依据能区分它们；可靠的判定需要整页上下文
  （整页出现过假名就按日文处理），当前的核心层是纯函数、不持有页面状态，所以不做
  （详见 `src/core/lang.ts` 里 `shouldSkip` 的注释）。含假名的日文不受影响。
- 语言判定按**字符集**（中文 / 日文 / 韩文 / 俄文 / 阿拉伯文 / 拉丁）分档，只在目标字符集
  **严格领先**时才跳过；分数持平（例如极短的混排 `Hi 你好`）一律照常翻译——宁可多翻一遍，
  也不要静默漏翻。

### 渲染

- **含行内标记（链接、加粗）的段落不做整页替换。** 就地替换要写 `textContent`，会永久销毁
  段落里的 `<a>`、`<b>` 等行内元素。当前 `displayMode` 恒为 `bilingual`，这条替换分支
  实际上不会被走到；等到整页替换上线时，这类段落会退回双语注入而不是破坏原文。
- 表格用单元格级译文，但**复杂布局（`position: absolute` 的浮层、跨行跨列的复杂表头、
  画布内文字）不做特殊适配**——译文可能位置不佳，请用 `Alt+T` 还原。
- 页面结构在翻译过程中被前端框架重建时，译文宿主可能被一并移除；重扫属下一阶段。

### 其他

- 单页面翻译期间弹窗主按钮会置灰，超过 30 秒仍未完成时弹窗会提示"重新打开弹窗查看进度"——
  这是**预期行为**，几百段的页面本来就会超过这个时限。
- 翻译结果缓存在 `chrome.storage`（会话级 + 持久级两层），缓存内容包含原文与译文；
  它不包含 API Key。
