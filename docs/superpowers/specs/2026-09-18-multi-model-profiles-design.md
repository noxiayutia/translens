# 一个档案接入多个模型并可切换

日期：2026-09-18 · 状态：已与用户确认方向 · 关联：`2026-09-18-options-page-redesign-design.md`（§9 单元 C）

## 1. 需求

用户原话：**「一个服务商可以接入多种模型且可以自行更换」**。

今天 `EngineProfile.model` 是**单个字符串**，所以想用同一家接口的两个模型，只能把同一个
`baseUrl` + 同一个 Key 复制成两份档案——用户现在的 4 个档案里就有这种重复。

## 2. 已确认的两个决定

- **模型清单来源**：手填 + 一键从 `{baseUrl}/models` 拉取勾选。**必须有手填兜底**——
  不是所有服务商都实现了这个端点。
- **切换入口**：设置页管理清单（增删 + 设为当前）；弹窗选完档案后，**当该档案的模型数 > 1 时**
  多出一个模型下拉（只有一个模型时不显示，避免噪声）。切回某档案时**记住它上次用的模型**。

## 3. 数据模型（v3 → v4）

```ts
export interface EngineProfile {
  id: string;
  label: string;
  baseUrl: string;
  models: string[];      // 候选清单，可为空（用户还没填）
  activeModel: string;   // 当前使用；'' = 未选。必须是 models 的成员或 ''
  apiKey: string;
}
```

**只有一个"当前模型"概念，不引入 `defaultModel`。** 理由：既然要"记住上次用的"，
`activeModel` 本身就是持久化的当前值，再加一个"默认"只会产生"这俩哪个说了算"的困惑。

### 3.1 必须守住的不变量

`activeModel === '' || models.includes(activeModel)`

破坏它的唯一路径是**删除当前模型**。删除时自愈：取 `models` 的最后一个作为新的 `activeModel`；
清单空了就置 `''`。**这条要有专门的测试**（它不是理论风险，是删一下就会踩到的）。

### 3.2 迁移

`CURRENT_VERSION` 3 → 4。v1/v2/v3 三条路径都要收敛到同一形状：

```
model: 'deepseek-chat'   →   models: ['deepseek-chat'], activeModel: 'deepseek-chat'
model: '' 或缺失          →   models: [], activeModel: ''
```

**沿用 v2→v3 那次的教训**：`saveSettings` 是**整体覆盖**写的，所以旧字段不能指望默认值兜——
必须在 `migrate()` 里显式搬。那次「默认显示模式改不动」就是这么来的。

### 3.3 没有模型时必须报错，不许发请求

`activeModel === ''` 的档案被选中时，`resolveEngine()` 要返回**可读错误**
（「这个档案还没有模型，点『添加模型』或『拉取可用模型』」），
**不能**带着空 `model` 去打接口——那会换回一个 HTTP 400 加上一句看不懂的英文，
正是上次 `deepseek` 那次事故的形状。

## 4. 缓存正确性：已核实，无坑

`scheduler.ts:189` 的 `configHash` 里**已经含 `model`**：

```ts
const configHash = hashString(JSON.stringify({ baseUrl: ..., model: deps.engineConfig.model ?? '' }));
```

所以换模型天然不会命中上一个模型的译文，**不需要**为它改缓存 key。
但仍要有一条测试钉住这个前提（万一将来有人把 `configHash` 收窄，多模型就会串味）。

## 5. `/models` 拉取

### 5.1 谁去发这个请求

**后台 service worker**，不是设置页。设置页**只传 `profileId`**，由后台自己从存储读那份档案的
`baseUrl` 与 `apiKey`。

理由：设置页持有全量设置（含 Key），如果让它把 Key 塞进消息回传后台，等于把密钥又搬过一条通道，
与现有「Key 不进内容脚本、不渲染进设置页 DOM」的隔离口径自相矛盾。**这条要有成对的隐私测试**：
断言消息体里不存在 `apiKey` 字段。

### 5.2 响应形状的宽容解析

OpenAI 兼容没有统一形状，至少三种要认：

```
{ data: [{ id: 'gpt-4o' }, ...] }     // OpenAI / 多数兼容网关
{ models: [{ name: 'qwen2.5:14b' }] } // 部分实现
[ { id: '...' }, ... ]                // 直接给数组
```

条目取 `id ?? name`，**非字符串一律丢弃**；整体解析不出任何一条时按"该服务商不提供模型列表"处理，
**引导手填**而不是报错完事。

### 5.3 失败分类与超时

网络不可达 / 401 / 404 / 非 JSON / 超时（**10 秒**，独立于 `BACKGROUND_TIMEOUT_MS`）
→ 各自一句能读懂的话，且**永远保留手填路径**。复用 `api-error.ts` 的 `extractErrorDetail`，
不要把响应体丢掉。

### 5.4 与「零遥测」承诺的关系

这是**用户点一下按钮才发**的一次请求，目标是他自己配置的地址，不是遥测。
规格上明确：**不得自动拉取**（打开设置页不拉、切换档案不拉、聚焦输入框不拉）。

### 5.5 权限

`{baseUrl}/models` 落在档案保存时已申请的 origin 范围内，**不需要新权限**。
若拉取因权限失败，提示指向「重新保存该档案以授权」。

## 6. 设置页 UI（档案行与编辑面板）

版式参照用户提供的参考图（另一个扩展的界面）。**有两处必须偏离参考图**，理由写在各自那一条里。

### 6.1 折叠行（一行一档案）

```
┌ 我的 DeepSeek  使用中  自定义  ●            [编辑] [删除] ┐
│  https://api.deepseek.com/v1 · deepseek-chat             │
└──────────────────────────────────────────────────────────┘
```

- 左侧一行：`名字` + `使用中`徽章（仅 `engineId === id` 时）+ `自定义`徽章（**仅当该档案的模板不是
  预设时**）+ 状态点（三态沿用改版规格 §4.3 的 `data-state`：`ok` / `idle` / `bad`）。
- 右侧两个按钮：`编辑`（展开 / 收起这一行的编辑面板）、`删除`。
- **改动**：改版规格里的"点整行展开"改成"点「编辑」展开"。折叠行右侧现在还有「删除」，
  整行可点会把删除变成一次误触。
- **偏离一（保留次级 meta 行）**：参考图的折叠行只有名字，把"打哪个地址、用哪个模型"藏进折叠面板。
  我们**保留** `接口地址 · 当前模型` 这一行（未填时各写一个占位：`未填接口地址` / `未选模型`）。
  理由：5 个档案时"哪个档案打哪个地址、用哪个模型"是一眼就该看见的信息；参考图把它藏进面板是它的
  取舍，我们不跟。这条是**有意偏离**，记在案。

### 6.2 编辑面板（由「编辑」进入）

自上而下：

1. **名字**：`.profile-label` 输入框。参考图的面板首行只是名字文本，而我们的名字**必须可编辑**，
   所以这里放输入框——**偏离二**。
2. **API 密钥**：`type=password` + 「显示」切换（沿用现有 `.profile-toggle-key` 机制）。
   占位符：**已配置时**写「已配置——输入新值可替换」，未配置时给引导语。语义不变：
   **留空 = 保留存储里当前的 Key**（不回填、不进 DOM）。
3. **可折叠的「自定义设置」**（原生 `<details>`）：里面放 `服务商模板` 下拉与 `接口地址` 输入框。
   **默认展开规则（明确一条）**：`baseUrl` 为空时展开，否则折叠。理由：地址为空意味着"这个档案还没
   接上任何端点"，而模板与地址是唯二能把它接上的控件——折叠起来会让面板首屏没有任何能填地址的地方，
   用户会以为没有这个入口；反过来「模板 = 自定义」**不**触发展开：「自定义」是"用户手改过地址/模型名"
   的正常状态，已有地址的档案再展开它只会白占一屏。
4. **模型目录**：清单每行 = `模型名` + 当前项徽章`当前` + 行内 `设为当前`、`删除` 两个按钮；
   下方虚线按钮 `+ 添加模型`（手填：**空值与重复值不写入**）；右上角 `⟳ 获取可用模型`
   （**点它才请求**，§5.4 的"零自动拉取"不变）。清单为空时显示一句**如实的**说明：

   > 清单为空时，弹窗里不显示模型下拉——点「添加模型」手填一个即可；拉取到的清单会先让你勾选，
   > 再并入这里。清单只有一项时弹窗也不显示下拉，直接用那一项；两项以上才会出现下拉。

   （参考图那句「目录外 ID 仍可直接发送」对我们**不成立**：我们的不变量是
   `activeModel === '' || models.includes(activeModel)`，想用别的模型就把它加进清单。）
   - 「获取可用模型」的结果用**勾选清单**呈现（默认全不选），确认后并入现有列表、去重。
   - **谁在清单里"当前"**：手填添加成功的那一项即设为当前；拉取并入时，只有当清单原本为空才把
     并入的第一项设为当前（清单非空时不动用户已经选好的那一个）。不这么定的话，用户刚加完模型，
     档案仍停在"还没有模型"（§3.3），还得再点一次「设为当前」。
   - 手填**不校验模型名**：服务商认不认识这个名字只有它能回答（错误在翻译时由服务商正文给出）。
   - 删除是红字、添加是虚线按钮——与改版规格的列表语言一致。
   - 拉取用的是**存储里**那份档案（后台自己读），面板里还没保存的地址/Key 改动不参与。
5. **底部按钮行**：左 `测试连接`（§4.3 的三态状态点靠它更新，**必须保留**）；
   右 `取消`（**显式丢弃**本行的编辑并收起面板：连同这一行的内存暂存一起清掉）与 `保存`
   （语义与既有的「保存档案」一致：含"留空 = 保留原 Key"，并在用户手势里申请该地址的宿主权限）。
   **`取消` 与"隐式收起"是两回事**：点另一个档案的 `编辑`、点本行收起、切到草稿行都算隐式收起，
   它**保留**未保存的输入（每行一份内存暂存，见 §9 第 19 条）。

### 6.3 字符图标

可以用 `⟳`（搜索框已有 `⌕` 先例）。**不许**引入图标字体或 emoji 依赖（PUA 字形有已知限制）。

## 7. 弹窗 UI

- 档案下拉（现有）→ 其后追加模型下拉，**仅当 `models.length > 1`** 时渲染。
- 换模型后**不自动重翻**当前页面；给一句提示：「换模型后需重新翻译（`Alt+T`）才会用新模型」。
  缓存 key 含 model，所以重翻不会命中旧模型的译文。

## 8. 非目标

- 每个模型单独的 temperature / max tokens 等参数（只有 `model` 这一个维度可变）
- 模型能力探测（上下文长度、是否支持函数调用）
- 自动翻译与站点规则（分属另两个单元）
- 档案内多 Key（一家接口多个 Key）

## 9. 验收标准

1. v3 存储里的单 `model` 迁移成 `models:[model]` + `activeModel:model`，**旧 Key 与 baseUrl 不丢**。
2. 删除当前模型后 `activeModel` 自愈且不变量成立；清空列表后为 `''`。
3. `activeModel === ''` 时选中该档案：得到可读错误，**零网络请求**。
4. 三种响应形状各解析出正确模型名；解析不出时文案指向手填。
5. 拉取请求的消息体**不含 `apiKey`**（成对断言：后台确实拿到了 Key）。
6. 打开设置页 / 切换档案 / 聚焦输入框均**不触发**拉取（零自动请求）。
7. 弹窗模型下拉在 1 个模型时不存在、2 个时存在；切回档案记住上次选的模型。
8. 换模型后 `configHash` 变化（钉住 §4 的前提）。
9. 全量 `npm test` / `typecheck` / `build`（`verify:dist` 14 项）/ `zip` 全绿。

### 9.1 §6 版式与交互的验收项（`2026-09-20` 追加）

10. 折叠行同时具备：名字、`自定义`徽章（**仅当**模板不是预设；地址命中某个预设时**没有**它）、
    三态状态点（`data-state`）、右侧 `编辑` 与 `删除` 两个按钮；`engineId === id` 时保留「使用中」徽章。
11. 折叠行有次级 meta 行（`接口地址 · 当前模型`，未填时各写占位）——这是对参考图的**有意偏离**（§6.1）。
12. 编辑面板由「编辑」进入（不再点整行）；面板里有：可编辑的名字、带「显示」切换且占位符区分
    "已配置 / 未配置"的 Key、按 §6.2 规则默认折叠的「自定义设置」、每行带 `设为当前`/`删除` 的模型
    目录、虚线 `+ 添加模型`、右上角 `⟳ 获取可用模型`、底部 `测试连接` / `取消` / `保存`。
13. 「取消」**显式丢弃**本面板的编辑（含它的内存暂存）并收起面板，**存储一个字节都不动**；
    再点「编辑」看到的是存储里的值。
14. 展开 / 收起**只动受影响的那一两行**：单次展开对 DOM 的改动量与档案数无关（N=5/20/50 同值）；
    展开 B 时 A 的编辑器**必须不在 DOM 里**、A 的触发按钮 `aria-expanded` 回到 `false`。
    （本机没有浏览器，这条只到 jsdom 的 DOM 变更计数；真机绝对耗时未经测量，见 §10。）
15. 模型清单为 0 项或 1 项时，弹窗都**不**渲染模型下拉；2 项及以上才渲染，并选中该档案的 `activeModel`。
16. 手填 `+ 添加模型`：空值与重复值不写入；**添加成功的那一项即设为当前**。拉取并入时，
    只有当清单原本为空才把并入的第一项设为当前。
17. 没有当前模型时点「测试连接」：得到那句可读的话、**零请求**（与"有当前模型时真的发请求"成对）。
18. `activeModel` 认不出来（不是 `models` 的成员 / 空值 / 缺失）时，读取边界置 `''`，
    **不替用户挑一个**：自动选一个就等于"用户没选、插件替他选了，下一次翻译就用了它"。
19. **隐式收起保留未保存的输入**：点另一个档案的 `编辑`、点本行收起、切到草稿行之后再切回来，
    那四个字段（名字 / 接口地址 / API Key / 模型清单）**必须还是用户刚才敲进去的样子**
    ——每行一份内存暂存，收起时存下、展开时先填暂存（没有暂存才用快照）。
    三条边界必须各自成立且**互不覆盖**：`保存` 成功后清掉该行暂存、`取消` 清掉该行暂存、
    行被删除（或草稿行被取消）时清掉它的暂存。**这不是自动保存**：暂存只在内存里，
    半填的档案绝不被静默写进存储（见 §10.1 第 11 条）。

## 10. 已知限制与风险

- **本机没有浏览器**，弹窗新增一行下拉后的排版、拉取结果勾选清单的观感，均未经真实渲染验证。
- `/models` 返回的清单可能**极长**（有些网关列几百个），本轮只做"可滚动 + 勾选"，不做搜索框——
  若实测难用再加，不预先造。
- 部分服务商 `/models` 返回的是**全部模型**而非用户可用模型，勾选清单因此必须允许手填修正。
- 迁移只向前：v4 的存储被旧版本扩展读到时会走 `pickProfiles` 的容错路径（读不到 `model` 字段
  → 空串），**不会崩**，但会显示成"没有模型"。降级兼容不做。

### 10.1 §6 版式的限制（`2026-09-20` 追加）

5. **参考图的两处偏离**（§6.1 的次级 meta 行、§6.2 的名字输入框）与"点「编辑」展开"都是**设计决定**，
   不是权宜。折叠行在窄窗口下的挤压、`自定义设置` 的折叠观感、模型目录各按钮的排布
   **均未经真实渲染验证**（本机没有浏览器）。
6. **"展开变快"的读数只到 jsdom 这一层**：钉住的是"单次展开对 DOM 的改动量不随档案数增长"
   （DOM 变更计数），**不是**真机耗时——真机绝对耗时本机测不了。用户复测若仍慢，
   下一步是加临时 `console` 计时探针定位。
7. `+ 添加模型` 只做"非空 + 不重复"两条判据，**不校验服务商认不认识这个模型名**：
   填错会在翻译时拿到服务商自己的 400（错误码 `BAD_REQUEST`，正文原因由 `extractErrorDetail` 展开）。
8. 模型清单**没有条数上限**：`/models` 返回几百条时勾选清单很长（只做可滚动 + 勾选，不做搜索框）；
   存储里的 `models` 也只逐条 trim / 去重，不截断。
9. **`activeModel` 认不出来时置 `''` 而不是挑一个**（§9 第 18 条的代价）：手改存储造成"清单非空
   但没有当前项"时，用户看到的是 §3.3 那句话，需要自己去点「设为当前」——我们不替他选。
10. **拉取读的是存储里的那份档案**：面板里改了地址 / Key 但**没点保存**就点「获取可用模型」，
    拉的是存储里那份（后台按 `profileId` 自己读）。草稿行（还没保存过）直接明说"先保存一次"。
11. **未保存的编辑只活在内存暂存里**（每行一份，见 §9 第 19 条）：隐式收起再展开能保住它，
    但**关掉设置页就没了**，也不会落盘。它不是自动保存——半填的档案在任何路径下都不会被静默写进
    存储（这是"档案仍用「保存」按钮"那条纪律的另一面）。

## 11. 交付顺序

排在**单元 B（设置页改版）之后**：B 会把 `options.ts` 拆成 `sections/`，
本单元要改的档案编辑框正好在 `sections/engine.ts` 里。
（**路径以仓库为准**：本节只是交付顺序说明，文件名按当时的仓库；改版当时那份草稿把它写成了
`sections/翻译引擎.ts`，仓库里从来没有这个文件。）
先做 B 再做 C，可以避免在旧结构上改一遍、改版时又重写一遍。

单元 A（站点规则行为）与本单元无依赖，可并行。
