# 划词小气泡最小化（单元 F）设计规格

日期：2026-09-24 · 状态：**已实施**（`200e5b1` 形态与交互 + `ca0b789` README 同步 + 本次的键盘读数）· 关联：`src/content/selection.ts`、`src/content/tooltip.ts`

> **本文 §2「现状」是动手之前的快照，保留不改**（它是这份设计的起点，删掉就没人知道为什么这么切）。
> 实施后的活稿在 `2026-09-24-selection-hover-chip-design.md`。三处与本文的出入，逐条点名：
>
> 1. **无障碍名**：本文写 `aria-label="翻译"`，实施用的是 **`翻译选中的文字`**——用户在实施指令里
>    明确给了这个名字（视觉无字、可达名要说清"翻的是什么"）。
> 2. **DOM 结构**：本文要"气泡本体就是一个 `<button>`"，实施是 `.jy-bubble > .jy-actions > button`
>    且**按钮撑满气泡**（padding 0、30×30、圆角 999px）。用户可见与键盘可达的后果一致
>    （真机 ⑮：Tab 4 次直达圆点、Enter 进第二阶段），没有换第二层可聚焦元素；不改成本体是
>    `<button>` 的硬约束——骨架必须常驻、`.jy-text` 是 `role=status` 的活区节点，换节点等于换区域。
> 3. **§3 那个 8px gap 死区**：不会发生，因为圆点这一档把 `display:flex; gap:8px` 整个去掉了
>    （`padding: 0` + 按钮撑满）。读数按本文要求补了：① 断言圆点 **30.0×30.0**（宿主含描边 32×32），
>    多一个 gap 槽就会当场红。

## 1. 用户诉求与已确认的决定

用户原话：**「划词后应该出现的是小气泡，而不是直接一个框（无需提示悬停翻译等），划词后只给个小气泡就行，悬停小气泡或点击小气泡再弹出译文框和复制按钮」**；追问小气泡里放什么，回答：**「无字」**。

| 决定点 | 结论 |
| --- | --- |
| 可见文字 | **一个都不出现**（含提示语与按钮标签） |
| 可见内容 | **只有一个图标**（沿用既有 `ICONS.translate`） |
| 进第二阶段的路径 | **悬停 150ms** 与 **点击气泡本体**，两条都保留 |
| 第二阶段 | **完全不变**（译文 + 唯一的实心主按钮「复制」） |

> 「无字」在追问里给了两条解释路径（"只有图标、无文字" / "连图标也不要、只剩小圆点"）。**本规格取前者**：图标不是文字，且无图标的小圆点在真机上没有可点性暗示。若用户后续要求后者，改动面是"去掉图标 + `aria-label` 照旧"，与本文其余部分不冲突。

## 2. 现状（事实，全部来自代码，不靠记忆）

**两阶段交互已经存在**，用户现在抱怨的是**第一阶段的观感**：

- 划词后走 `showChip()`：注释原文「第一段：**只弹小气泡，零请求**」——**选中不产生任何请求**，这点已经是既成行为，本单元不动。
- 小气泡的内容是 `CHIP_HINT`（字面 `'悬停或点击翻译'`）**加**一个 `label: '翻译'`、`icon: 'translate'` 的按钮，整体是 `variant: 'chip'`——`tooltip.ts` 对它的描述是「一行摆下提示语与「翻译」按钮的紧凑尺寸」。**这就是用户看到"一个框"的来源。**
- 进入第二阶段有两条路：`hoverIntent`（`delayMs = DEFAULT_HOVER_DELAY_MS`，值 150）**或**点那个「翻译」按钮。后者不是装饰：`showChip()` 的注释写明「纯悬停对键盘用户是死路，这是确定入口」。
- 第二阶段由 `showTranslation()` 渲染：成功 = 译文 + 唯一实心主按钮「复制」；失败 = 只有错误文案、**不挂按钮**（没东西可复制）；请求中先渲染 `PENDING_TEXT`（`'翻译中…'`）。
- 关闭与失效：点外部 / Escape / 滚动关闭；`generation` 世代机制保证"更新的划词或被接管的一轮"丢弃旧结论。
- 定位与悬停意图的真机结论都在 `tooltip.ts`：`layoutTooltip` + caret + `GAP`/`MARGIN`/`CARET_INSET`；`armHoverIntent` 的**起算挂在 `move` 而不是 `enter`**，理由是拖选越过最后一行的行底时 chip 会生成在静止的指针底下（真机台架 `.qa/run-selection-chip.mjs` 的 ⑭ 定的）。
- `tooltip.ts` 在 chip 换成 pending 那一屏时会**当场作废悬停意图**（防止指针停在原地补发第二次）。

## 3. 目标形态

**第一阶段的 DOM 与语义**

- 气泡本体就是一个 `<button>`（可 Tab 聚焦、Enter/Space 触发），**视觉上无文字**：只放 `ICONS.translate` 的图标。
- `aria-label="翻译"`（视觉无字、**可达名必须有字**）；图标元素 `aria-hidden="true"`。
- 删除 `CHIP_HINT` 常量与它的引用——**不留死常量**。
- 尺寸沿用 chip 那一档的紧凑内边距（去掉文字那一行之后，`variant: 'chip'` 的规则自然收窄）；**不新增 CSS 变量**。
  ⚠ **实现细节（会咬人）**：chip 那一档是 `display: flex; gap: 8px; padding: 6px 8px`，**没有显式宽度**——所以收窄靠的是"子节点变少"。但**空的 `.jy-actions` 仍然是一个 flex 项，会白占一个 8px 的 gap 槽**：合并之后要么不渲染它、要么把它摘掉，否则气泡右侧多出 8px 死区。收窄因此**不是全自动的**，落地后要有一条 DOM 读数确认气泡里只剩图标那一个子节点。
- 定位、`hoverIntent`（150ms）、世代机制、关闭时机**一律不动**。

**为什么这样切**：把一个"带说明文字的框"变成"一个图标按钮"，同时把原来嵌在里面的「翻译」按钮的职责**上移到气泡本体**。键盘可达性因此**不降级反而更好**：现状要在气泡容器与内部按钮之间 Tab，改后一次 Tab 就到。

**第二阶段**：一行代码都不改（译文 + 复制 / pending / 错误无按钮）。

## 4. 必须处理的边界

1. **误触面积变大（本单元唯一的真风险）**：现状只有内部那个小按钮可点，改后**整块可点**。拖选时指针扫过气泡是否会误触发，**必须有一条真机读数**（台架 `.qa/run-selection-chip.mjs` 正是这类场景的既有工具）。
   备选缓解（**先测再定，不预先实现**）：① 只让图标那一小块是点击目标；② 要求指针在气泡上**静止 ≥150ms** 才算点击意图。
2. **悬停意图的一次性保护**沿用（触发过就摘掉，指针再进再出不会补发第二次）。
3. **chip → pending 切换时作废意图**的既有行为沿用。
4. **焦点环**：气泡成为可聚焦控件后，`*:focus-visible` 的焦点环必须可见（既有全局规则覆盖，实现后要有一条 DOM/样式断言）。
5. **进入第二阶段后的焦点落点**：气泡本体消失时，焦点会落到 `body`——键盘用户要重新 Tab 才能到「复制」。**这是现状就有的行为**（现在消失的是内部按钮），不是本单元引入。
   **本单元不做**（范围纪律：本单元只改第一阶段的形态与交互合并），改由 **README 已知限制**如实写明；将来要做，做法是"进入第二阶段后把焦点移到「复制」按钮"，属独立的可访问性小改动。

## 5. 测试面（实现者按此改）

- **改**：现在钉 `CHIP_HINT` 文案的断言 → 改成钉下面**三条同时成立**（缺一条就有一类静默回退）：
  ① 气泡本体的 `textContent.trim() === ''`（**"无字"就是这个单元的契约**）；
  ② `aria-label === '翻译'`（视觉无字、可达名有字）；
  ③ 气泡本体是可聚焦控件（`<button>` / 可 Tab），Enter 能进第二阶段。
  这是本单元的**核心守卫**：将来有人顺手把提示语加回来，①必须当场红。
- **改**：键盘路径断言从"点气泡**内部**的「翻译」按钮"改成"**Tab 到气泡本体 + Enter**"。
- **不动**：第二阶段的三种态（译文 + 复制 / pending「翻译中…」/ 错误无按钮）、`hoverIntent` 的 150ms 行为、世代丢弃、关闭时机——**一条都不许放松**。
- **新增**：点气泡本体进第二阶段的用例（与悬停那条成对）。
- **新增（真机）**：§4.1 的误触读数。

## 6. 验收

1. `npx vitest run` 全绿；`npm run typecheck` exit 0；`npm run build` exit 0 + `verify:dist` 14 项。
2. 真机（用户那台 Chrome，或台架）逐条确认：划词后**只有图标**；悬停 150ms 进译文；点气泡进译文；**Tab + Enter 进译文**；拖选越过气泡**不误触发**（或按备选缓解后不误触发）；点外部 / Escape / 滚动关闭。
3. 行为面**零改动**：选中仍然零请求（`showChip` 的既有承诺）；第二阶段三态不变。

## 7. 已知限制

- **可发现性换简洁性**：一个没有文字的图标气泡，用户不一定知道点它会翻译。若真机上觉得不可发现，退回"图标 + 极短标签"是**一行改动**（把 `aria-label` 的内容同时显示出来）。
- **本机没有浏览器**：误触与观感**只能真机验**（与规格 §11 同一天花板）。
- 焦点落点（§4.5）若不修，键盘用户进入第二阶段后需要重新 Tab。

## 8. 交付拆分（供实施计划使用）

- **F1** 气泡形态：`<button>` + 图标 + `aria-label`、删除 `CHIP_HINT`、CSS 收窄（chip 档）。
- **F2** 交互合并：点气泡本体进第二阶段；悬停路径保持；键盘路径改 Tab + Enter。
- **F3** 守卫与验收：§5 的改/增断言、§6 全量读数、§4.1 的真机误触读数（若成立则落备选缓解并补读数）。
