# 划词两段式（小气泡 + 悬停意图）· 规格与两条真机硬知识

> **规格 · 2026-09-24。** 实现落在 `src/content/selection.ts` + `src/content/tooltip.ts`，
> 判据落在 `tests/content/selection.test.ts` + `tests/content/tooltip.test.ts`，
> 真机读数落在 `.qa/run-selection-chip.mjs`（13 条，本文末尾原样抄录）。
> 设计文档 §4.2 的「划词气泡」条目已同步改成本文这一版。

## 1. 状态机

```
IDLE ──左键划词(真实手势 + 合法选区 1~2000 字)──→ CHIP（紧凑小气泡，零请求）
CHIP ──指针停在气泡上 ≥150ms ─────────────────→ 发请求（pending → 译文 / 失败）
     ──点击气泡上的「翻译」按钮 ───────────────→ 同上（键盘与不想等延时的确定入口）
     ──点外部 / Esc / 滚动 / 新划词 / 页面还原 ─→ 关闭，并作废未到点的计时与在飞请求
译文态 ──移开指针后译文保留（与悬停翻译「移出保留译文」同一口径）
```

改这一条链路的理由只有一个：**原来一划中就翻**。拖选时顺手带上的半句、错行、整段照发，
中间没有任何一步在确认"这段真是你要翻的吗"。多出来的那一次停留就是那次确认。

参数与职责边界：

| 项 | 值 | 住在哪 | 为什么 |
| --- | --- | --- | --- |
| 停留时长 | `DEFAULT_HOVER_DELAY_MS = 150` | `selection.ts` | 悬停翻译的先例是 180ms（`hover.ts`），这里更短因为指针是**故意**移到气泡上的。全仓只有这一份数字：`TooltipHoverIntent.delayMs` 是**必填**，浮层不替调用方藏默认值 |
| 计时器、进入/离开、一次性 | — | `tooltip.ts` | 只有浮层知道这个气泡什么时候被换掉、什么时候被关掉。"气泡关了、计时器还在，到点偷偷发一次请求"是这里唯一的失效形状，所以 `hideTooltip()` 必须清计时 |
| 世代号 `generation` | — | `selection.ts` | 一次推进同时作废三样：未到点的意图、在飞请求、迟到的结果 |
| 提示语文案 | `悬停或点击翻译` | `selection.ts` | 悬停是隐形的，不写出来没人会发现这条路径 |
| 「翻译」按钮 | 次按钮（半透明白底） | `selection.ts` | 小气泡是"待触发"，不该用比结果屏更强的强调色去抢悬停那条主路径 |

**不动的东西**：`isTrusted` 真实手势闸门、可编辑区域两端判定、插件自身浮层的自翻译循环判据、
1~2000 字符上限、浮层恒挂 `documentElement` 且 `body.innerHTML` 逐字节不变、定位数学（两档共用
同一份 `positionTooltip`，没有第二套）。右键菜单「翻译选中文本」**仍立刻翻**——那是用户逐次
明确的动作，不该再被问第二次。

## 2. 真机逼出来的两条硬知识（注释不承担规格职责，所以写在这里）

### 2.1 落在浮层里的 `mouseup` 不是"又划了一次词"

按下浮层里的按钮时，浏览器先派发 `mouseup`，而**页面上上一次划的选区还在**——只看选区的判据
一律放行。旧逻辑于是把这一下当成新划词：重开一个小气泡 → `renderBubble` 用 `replaceChildren`
把**刚被按下的那个节点**换掉 → Chrome 对"按下与抬起的目标已断开"的这一对**不再合成 click**。

真机现象（`.qa/probe-click3.mjs`）：`mousedown`/`mouseup` 都带着正确的 `composedPath` 到了按钮，
`click` 永远不来，抬起那一刻 `button.isConnected === false`。

**这条不是新引入的**：同一个机制让既有的「复制」按钮在真机上从来没生效过。jsdom 会把手工
`dispatchEvent` 的 click 打进已脱离文档的节点，回调照跑、断言全绿——所以它不可能被单测抓到。

修法：`tooltip.ts` 导出 `isEventInTooltip(event)`（判据是 `composedPath`，`closest()` 不跨
shadow 边界），`onMouseup` 在 `isTrusted`/主键之后立刻据此早退。
**判据**（两侧同口径）：`mouseup` 派发途中（产品监听器之后、click 之前）`button.isConnected === true`。

### 2.2 悬停意图只认 `pointerenter`，而 chip 的几何决定了它压不到静止的指针

计时器的起算点是 `pointerenter`。chip 的顶边 = 选区块底 + `GAP`(8)，而任何仍然命中该行文本的
落点都在块底之上 ⇒ **单次划词时 chip 永远出现在指针下方，盖不到指针**。真想让盒子压在静止的
指针底下，只有"拖选越过最后一行的行底"那一种。

结论与代价：指针必须**移动到气泡上**才开始计时，原地不动不会自己翻。这是选择，不是遗漏——
"停在上面"的定义就是用户主动把指针放上来，不为"已经压在上面"补一次猜测。确定入口是那颗
「翻译」按钮。README 的划词那一行与本文都写明了这一点。

台架侧的连带事实（写下来免得下次重新试）：**CDP 的 `mousePressed` + `mouseMoved(buttons:1)` +
`mouseReleased` 拖不出文本选区**（事件确实以 `isTrusted=true` 送到页面，但 Blink 不扩展选区；
加不加掩码都一样），所以真机场景里的"划词"一律用**双击选词 + Shift+单击扩到句尾**；
另外双击单个字母的词（"A single helper…" 的 "A"）选不出东西，落点要挑多字母的词。

### 2.3 浮层里的按钮只认真实的 `click`

浮层是 **open** shadow DOM，页面脚本摸得到宿主，也就点得到里面的按钮——一条会把文本带着用户
自己的 Key 送去付费引擎（「翻译」），一条会写剪贴板（「复制」）。与 `mouseup`、`mouseover`、
`pointerenter` 同一类路径就同一类答案：委托层 `onHostClick` 首位 `if (!event.isTrusted) return;`。
门开在委托这一层，所以 `TooltipButton` 的回调契约不用带上事件对象。
