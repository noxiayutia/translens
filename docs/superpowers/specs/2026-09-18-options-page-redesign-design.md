# 设置页改版设计（信息架构 + 补齐区块 + 视觉语言）

日期：2026-09-18 · 状态：已与用户逐条确认 · 关联：`2026-09-14-immersive-translate-extension-design.md` §8

## 1. 问题

设置页只有 4 个区块、3 个可改设置项 + 一个清缓存按钮，而数据模型里已经有 **11 个字段一个 UI 都没有**。
「简陋」的两半原因都在这里：**内容单薄**（该有的设置没有）与**版式朴素**（单列卡片堆叠、隐私节是一整坨文字墙）。

实测过每个字段的消费者，据此把「能做的」和「做了就是骗人的」分开：

| 字段 | 消费者 | 能进设置页吗 |
| --- | --- | --- |
| `profiles` / `engineId` | 引擎注册表、后台 | ✅ 已有 UI |
| `targetLang` / `displayMode` | 后台、内容脚本 | ✅ 已有 UI |
| `sourceLang` | `scheduler.ts` → 请求 `from` + 缓存 key（`hash.ts` 点名它必须进 key） | ✅ 新 |
| `glossary` | `openai-compat.ts` `buildMessages()` 注入；`glossaryHash` 进缓存 key | ✅ 新 |
| `systemPrompt` | 同上（`promptHash` 进 key）；弹窗对不支持的引擎会警告 | ✅ 新 |
| `hoverTranslate` / `selectionTranslate` | 内容脚本；目前**只在弹窗里**有开关 | ✅ 新（设置页也露出） |
| `cacheMaxEntries` | `service-worker.ts` `setMaxEntries()` | ✅ 新 |
| `concurrency` / `maxBatchChars` / `maxSegmentsPerBatch` | `content/index.ts`、`core/segmenter.ts` | ✅ 新（收进「高级」折叠） |
| **`siteRules`** | **零个消费者**——只在 `settings.ts` 里声明、给默认值、被 pick | ⚠️ 见 §5，必须先实现 |
| **`autoTranslateDelay`** | **零个消费者** | ❌ 不做 UI（§8） |

**原则：不给没有行为的字段做控件。** 一排按了没反应的输入框比空着更糟——它会让人以为设置生效了。

## 2. 已确认的方向

骨架取 **A（左锚点导航 + 单列长滚动）**，视觉语言融合两份参考：

- **左导航**：图标 + 圆角高亮 + 活动项左侧 3px 强调条 + 分组用留白（不画分组标题线）。
- **列表**：**一行一卡片**、名称后跟状态点、**删除是红色文字按钮**（不是描边按钮）、**添加是虚线大按钮**。
- **成组开关**（语言/显示/悬停/划词）：用**一整块卡片 + 行间细分割线**，不做成一堆独立卡片。
- **刻意不抄**参考里的「搜索次数最多」快捷区：那要记录使用行为，与本扩展「零遥测」承诺冲突。

原型：`docs/mockups/options-ia-v2.html`（用户已看过并认可）。

## 3. 信息架构（8 组）

导航分三段：**翻译** / **内容控制** / **数据**。

1. **翻译引擎** — 档案一行一卡片：名称、`使用中` 徽章、状态点、`baseUrl · model`（等宽小字）、测试连接 / 编辑 / 删除。内置免费引擎不可删（不渲染删除）。
2. **语言与显示** — 目标语言、**源语言（新）**、显示模式。
3. **快捷翻译** — 悬停、划词两个开关（含「按住 Alt 时悬停暂停」的说明），快捷键与右键菜单只读展示 + 「去浏览器设置」。
4. **术语表（新）** — `from → to` 一行一卡片，虚线「+ 添加术语」。
5. **站点规则（新，见 §5）** — 域名 + 动作，「从当前页面填入」。
6. **自定义提示词（新）** — 多行文本，留空即使用内置提示词。
7. **缓存与请求** — 三个统计数字（已缓存 / 上限 / 并发）、缓存上限、清除按钮；`<details>` 里放并发与批量三项。
8. **隐私** — 三条一行式；那段「字段隔离 ≠ 内存级隔离」的诚实说明收进 `<details>`，**不删**。

## 4. 交互契约变更

### 4.1 即时保存（去掉「保存语言与显示」按钮）

8 组 25 个字段仍靠一个保存按钮，必然产生「改了没保存」与「改了哪块没保存」两种困惑。

- 选择类/开关类：**`change` 即存**。
- 文本类（档案、术语、规则、提示词）：**`blur` 时存**（边打字边写存储既吵又没必要）。
- 每次写回都基于**当前内存快照改一个字段后整体写回**，写回成功后更新快照。
- **已知代价（如实）**：同一扩展同时开两个设置页时，后写的一方会覆盖前一方。这与改版前"点保存即覆盖"是同一性质，本轮不解决，写进 §11。
- 保存失败必须可见：状态提示沿用现有 `.status` + `data-kind` 契约。

### 4.2 搜索（轻量版）

只做**区块与字段标签的过滤**，命中不到时显示「没找到」而不是留一片空白。

- 每个区块定义处随附一份**别名表**，与区块定义放在一起，避免两处漂移。别名必须指向**真正含该字段的区块**：
  「密钥 / key / API Key」归**翻译引擎**（Key 在那里），「词库 / 专有名词」归**术语表**——
  搜「密钥」跳出术语表比搜不到更糟。
- 占位符写「搜索设置」，**不写「搜索所有设置」**——不承诺搜不到的一切。
- 过滤只隐藏不匹配的区块，不改变 DOM 结构（避免与 §6 的测试契约打架）。

### 4.3 状态点三态

绿 = 最近一次测试连接通过；**灰 = 从没测过**（不代表可用）；红 = 最近一次测试失败，`title` 显示原因。
不照抄参考图那种「填了 Key 就点绿」——填了 Key 不代表能用（`deepseek` 那个 HTTP 400 就是活例）。

## 5. 站点规则：本轮的实现范围

`siteRules` 是死字段。直接给它做 UI 就是造一排假控件，所以本轮**先实现再露出**，且只做有真实语义的那一半：

- **只做「永不翻译」**。本扩展**没有自动翻译**，所以「总是翻译」目前**不产生任何可观察行为**——不给它入口，也不留占位。
- 新增纯函数 `matchSiteRule(rules, hostname)` 到 `src/core/`（可测、无 DOM），支持精确匹配与 `*.example.com` 前缀通配；规则自上而下、首条命中即生效。
- 拦截点：**整页翻译的三个入口**（右键菜单、`Alt+T`、弹窗按钮）命中「永不翻译」时不翻译，并给出可读提示；弹窗在该站点显示「此站已设为永不翻译 · 解除」。
- **本单元的闸只装在 `translatePage()` 上，管不到增量链路**：已翻译页面上**新出现**的内容
  仍走 `MutationObserver` 那条增量路径，**不受站点规则约束**。今天这个缝**实际不可达**——
  只有"删规则"这一侧，规则一旦命中整页翻译就进不去，也就没有"已翻译页面"可言；
  但**单元 B 把写入侧 UI 做出来的那一刻它就真的可读了**（用户可以在页面已翻译之后再加规则）。
  届时要在 README 的「已知限制 › 站点规则」补一句；要么在 `translatePage()` 之外把闸补到
  增量轮上，要么如实写进限制——**不要让它默默存在**。
- 与 `autoTranslateDelay` 一起，等**自动翻译**功能落地时再补「总是翻译」。

## 6. 必须一并修掉的过时文案

`options.html` 现在写：「仅译文」只显示译文（原文被隐藏，**段落里的链接点不了**，按 Alt+T 可还原）。

链接保留下划线/颜色/可点击**早已实现**，这句现在是**错的**，而 `tests/options/options.test.ts:295` 正断言它包含「链接点不了」。

改成如实的：仅译文模式下链接保留可点击；**多链接段落与文本占主的段落里链接仍可能失去下划线与可点击**（这是仍存在的限制）。
该断言随之更新——它钉的是已经不成立的说法，属于**修正**而非放宽，需在提交信息里写明。

## 7. 工程约束

- **入口文件名不变**：`src/options/options.html` 与 `src/options/options.ts` 保持原名（`manifest` 的 `options_ui` 与 `verify:dist` 的 14 项校验依赖它们），拆分只发生在内部模块。
- **`options.ts` 694 行必须拆**：`store.ts`（快照 + 读-改-写 + 即时保存）+ `sections/<name>.ts` 每组一个模块 + `options.ts` 只做装配。理由不是"行数多"，而是 8 个区块挤在一个文件里，每加一块都要重读全文件。
- **测试契约不得破坏**（`options.test.ts` 用 `DOMParser` 加载**真实的 `options.html`**，共用的是契约属性名）：
  `#profiles` `#engine-status` `#target-lang` `#display-mode` `#target-hint` `#add-profile` `#clear-cache` `#cache-status`、
  `.profile-row[data-profile-id]`、`data-action`、`.profile-editor`、`.profile-provider`、`#save`（见下）。
  新增区块一律用**新的**契约属性（`data-glossary-row` / `data-rule-row` 等），不复用旧名。
  `#save` 随即时保存移除，依赖它的用例改为等存储写入完成。
- **CSS 纪律**：所有颜色走 `:root` 令牌，亮/暗各定义一次，正文**不许出现硬编码颜色**，次级文字一律 `var(--text-2)` / `var(--text-3)`，不许用 `opacity` 充当次级文字（暗色下对比度不可控）。与 `popup.css` 共用的那组令牌保持逐字一致。
- **`*:focus-visible` 焦点环**保留；导航与折叠区键盘可达（`<details>`/原生按钮，不自造 widget）。
- **不得用 `innerHTML`** 渲染用户数据（术语、档案名、规则域名都是用户输入，必须走 `textContent`）。
- 分层守卫照旧：`src/core/` 不碰 DOM/`chrome`（`matchSiteRule` 是纯函数，放这里）。

## 8. 非目标

- 自动翻译与 `autoTranslateDelay` 行为（独立单元）
- 站点规则的「总是翻译」动作
- 把 API Key 拆成独立存储键（结构性隔离，独立单元）
- 术语表导入/导出、批量粘贴解析
- 多设置页并发写入的冲突解决
- 快捷键自定义（Chrome 要求用户手势，且扩展页无法代改）

## 9. 交付拆分

本设计含三件性质不同的活，**拆成三个可独立验收的单元**（各自 spec→plan→实现→核验），避免"页面改版"被"新功能实现"卡住：

- **单元 A：站点规则「永不翻译」的行为实现** —— `core` 纯函数 `matchSiteRule` + 三个整页翻译入口的拦截 + 弹窗状态与解除。它**先于**设置页的该区块完成：区块只在行为存在时才露出（§1 原则）。
- **单元 B：设置页改版** —— 信息架构、8 区块 UI、即时保存、搜索、状态点、§6 文案修正、`options.ts` 拆分。依赖 A 的只有「站点规则」这一个区块；其余 7 组可并行推进。
- **单元 C：一个档案接入多模型并可切换** —— 用户后补的需求，**另见 `2026-09-18-multi-model-profiles-design.md`**（自己的数据模型、v3→v4 迁移、`/models` 拉取与它的隐私口径）。**排在 B 之后**：B 拆出的 `sections/翻译引擎.ts` 正是 C 要改的地方，先 B 后 C 才不返工。C 与 A 无依赖，可并行。

## 10. 验收标准

1. 8 个区块全部可操作，**每个能改的字段都有真实消费者**（§1 表为凭）；无占位控件。
2. 即时保存：改任一字段后**重新读取存储**确认落盘（沿用现有"直读存储"断言风格），不点任何保存按钮。
3. 文本字段 `blur` 才写存储：打字过程中断言存储未变。
4. 术语表空行（`from` 或 `to` 为空）**不写入**存储。
5. 搜索：命中时只显示匹配区块；零命中时出现「没找到」文案，页面不留白。
6. 状态点三态各自可达且互不混淆；灰态 `title` 明说"从没测过"。
7. 站点规则：`never` 规则命中时三个整页翻译入口全部不翻译并给出提示；`*.x.com` 通配与精确匹配各有用例；自上而下首条命中生效有用例。
8. §6 的文案已改对，且断言更新在提交信息里写明理由。
9. 亮/暗两套下无硬编码颜色（用 `tests/helpers/css.ts` 的解析器断言声明块）。
10. 全量 `npm test` / `npm run typecheck` / `npm run build`（`verify:dist` 14 项）/ `npm run zip` 全绿。

## 11. 已知限制与风险（不粉饰）

- **本机没有浏览器/Playwright，无法做任何真实渲染验证**。布局挤压、窄窗口下左导航是否堆叠、长 URL 是否撑破卡片、暗色对比度——**全部依赖用户肉眼验收**。原型页本身也是未经渲染验证的产物。
- 左导航在窄窗口（<900px）需要降级为顶部横滚或隐藏，具体表现未经实测。
- 即时保存把"写存储"的频率从每次点按钮提高到每次失焦，`chrome.storage.local` 的写入量上升；量级很小（设置页不是高频界面），但未实测。
- 两个设置页并排打开时后写覆盖前写（§4.1）。
- 「永不翻译」只拦整页翻译的三个入口；**划词与悬停翻译不受站点规则约束**（用户主动发起的单段翻译，与"整页不该翻"是两件事）。这一点要在规则区块里写一句，避免误解。
