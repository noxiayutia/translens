## 1. 怎么测的

两条通道各测一半，互相补盲：

**A. 自动化台架（本机假引擎）**
用 CDP 的 `Extensions.loadUnpacked` 把 `dist` 挂进一个**独立临时 profile** 的 Chrome 153，
配一个指向 `http://127.0.0.1:8787` 的**本机假 OpenAI 兼容接口**（`.qa/mock-engine.mjs`，
可切 401/429/413/500/坏 JSON/坏标记/挂起等模式，并记录每次请求的 system/user 正文与计数）。
测试页面是自己写的夹具（含 `display:none`、`aria-hidden`、`<code>`、`contenteditable`、
纯图标按钮、重复文本、表格、行内载体、JS 动态注入节点、靠切 class 展开的菜单）。
好处：请求数、批次、缓存键、降级路径全部可精确计数。

**B. 你本人的 Chrome + 真实档案 + 真实页面**
通过 Qoder Browser Connector 驱动，在 `developer.mozilla.org` 的 `Document.querySelector`
页面上由你按 Alt+T 触发，我用 `domSnapshot` / 无障碍树 / 截图读回结果。
好处：真实模型、真实排版、真实站点噪音。

## 2. 结论摘要

核心链路在真机上**站得住**：整页翻译、仅译文/双语、还原逐字节复原、缓存零请求、
批次合并、同文本折叠、增量翻译、四类错误处理与两条降级路径、页面级提示的文案与优先级，
全部按 README 与规格的描述发生。测到 40+ 项行为，无一出现"静默失败"。

需要你处理的只有两处，都不影响主流程：

1. **屏幕阅读器专用文本（sr-only）会被翻译** —— 与 README 隐私一节的承诺不符，且白花额度。
2. **大页面（214 段）在真实模型下收敛很慢**，约 10 分钟后页面上仍有大量段落停在「翻译中…」，
   且这段时间里既不报错也不给重试按钮。这一条我**没能定论**，需要你 30 秒确认（见 §5）。

## 3. 已实测通过的行为（带读数）

### 3.1 整页翻译与还原（台架 A）

| 检查 | 读数 |
| --- | --- |
| 段落采集 → 译文宿主 | 14 段 → 14 个 `<jy-translation>`，每个都带 `data-jy-for` |
| 请求合并 | 14 段只发 **2 个请求**（`maxSegmentsPerBatch=12` 生效） |
| 仅译文模式 | 15 个 `[data-jy-originals]` 全部 `display:none`（藏起来而非删除） |
| 还原完整性 | `#article` 的 `outerHTML` 翻译前后**逐字节相同**（1454 = 1454） |
| 还原残留 | `jy-translation` / `data-jy-*` 全部归零 |
| 缓存 | 第二次翻译请求数 `2 → 2`（零新增），译文照常渲染 |
| 双语对照 | 原文可见 + 译文在场，无 `[data-jy-originals]` 包裹 |
| 中文页 | **零请求**，页面不插任何宿主 |

### 3.2 隐私与成本闸门（台架 A + B 双向确认）

`display:none` 段落、`aria-hidden` 段落、`contenteditable` 草稿、`<pre><code>` 代码、
纯图标按钮（`×`）**一个字符都没进请求体**（逐条在假引擎的请求日志里断言）。
真实页面上再加一条：MDN 页 **222 个 `<code>` 元素，0 个被插入译文宿主**。
同文本折叠：页面上两个「Read more」只被送出去 **1 次**。
接口返回的 HTML（`<img src=x onerror=alert(1)>`）只作为纯文本出现，**没有被解析成元素**。

### 3.3 增量翻译（台架 A，README 里最难兑现的一段，实测全部成立）

- 未翻译状态下新增 4 个节点：**零请求、零译文**。
- 整页译好后注入 3 张卡片：3 张全部补出译文，且**只新增 3 段**（没有重扫整页）。
- 往已译段落追加文字：不重译、不冒出第二个宿主。
- 靠切 `display` 展开的隐藏菜单：变可见后被补译。
- 还原之后：观察者确实断开，再注入 2 个节点零请求。
- 连滚 5 轮 × 2 段：`Δrequests=5`、`Δsegments=10` —— 线性，不是每滚一次重扫整页。

### 3.4 错误处理与降级（台架 A）

| 场景 | 实测行为 |
| --- | --- |
| HTTP 401 | 每段显示「API Key 无效或权限不足」，**不挂重试按钮**，原文回到可见，并弹页面级提示指路设置页 |
| HTTP 429 | 退避重试 500ms → 1500ms 后成功（请求数 2 → 4），译文正常落地 |
| 模型不按编号返回 | 降级为逐条翻译（请求数 2 → 14），最终 14 段全部译出 |
| 响应不是 JSON | 报可读错误「接口返回的不是合法 JSON：…」 |
| HTTP 500 | **把服务商写在响应体里的原因透传给用户**（实测显示 `接口 HTTP 500：Model Not Exist`） |
| HTTP 413 | 走句子级二次切分（请求数 15） |
| 混合错误码 | 第 1 批 401 + 后续 500 时，页面级提示**只弹 AUTH 那一条**（优先级择一成立） |
| 提示 | toast 文案完整、约 3.2s 自动消失 |

### 3.5 发给接口的内容（台架 A）

`system` 里依次是 `Target language: zh-Hans` → 固定规则 → **术语表**（`Glossary (must be used exactly): callback => 回调`）
→ **自定义提示词**；`user` 用 `<<<n>>>` 编号；`temperature` 固定 0；`model` 取自档案的当前模型。
改一次提示词会让同样的段落**重新翻译一次**（提示词确实在缓存键里）。

### 3.6 真实浏览器 + 真实档案（通道 B）

- 214 个译文宿主、244 个被藏起的原文 span；译文质量正常，术语处理得当（"返回值 / 异常 / 示例"）。
- 行内代码、`Copy` 按钮、侧栏 API 名（`Element`、`MutationObserver`…）保持原样未被改写。
- 链接密集的段落没有被整段涂蓝（6 处按 `LINK_WRAPPING_MIN_SHARE=0.6` 把译文包进链接，符合设计）。
- 全程无「失败/重试」标记，控制台无扩展抛错。

## 4. 发现的问题

### P2 · sr-only 文本会被翻译（文档与实现不符 + 轻微成本）

MDN 的 `<ul class="a11y-menu">` 里「Skip to main content / Skip to search」是**屏幕阅读器专用**
（用 `clip` / 1px 尺寸藏起来，不是 `display:none`，也不是 `aria-hidden`），实测被采集并翻译成了
「跳至主要内容 / 跳至搜索」。

- 与 README「只有在网页里**可见**的文本才会被送去翻译」这句**不符**——现在的可见性判据只挡
  `display:none` / `aria-hidden` / `visibility:hidden`，挡不住 clip 式 sr-only。
- 代价：这类站点每个页面白送几条请求文本，用户永远看不到结果。
- 可选补法（不新增请求，只加判据）：命中 `clip: rect(0 0 0 0)` / `clip-path: inset(50%)` /
  `width:1px;height:1px` 且 `overflow:hidden` 的组合，或 `position:absolute` 且尺寸 ≤1px 的元素。

### P3 · 大页面收敛慢，且这段等待期"看起来像卡住"（待你确认，见 §5）

真实 MDN 页 214 段，从按 Alt+T 起 **10 分钟后**视口内仍有约百个段落停在「翻译中…」。
期间：导航条在推进（两次截图之间从「翻译中…」变成中文），但正文标题/段落长期不变；
没有错误、没有重试按钮、没有 toast。

相关的两个既有设计叠在一起会造成这个观感：
- 批次并发固定 3、`maxSegmentsPerBatch=12` → 214 段约 18 批；真实模型每批十几秒就是分钟级。
- 后台超时是 **60 秒**（`BACKGROUND_TIMEOUT_MS`）→ 一批真要卡住，用户得先干等一分钟才拿到可重试的错误。

README 目前没有任何一句说明"大页面是分钟级、期间会大面积显示翻译中"，值得补进「已知限制」。

### P4 · 「为什么这段能点重试、那段不能」在界面上没有解释（设计边界，非缺陷）

`RETRYABLE_CODES` 只有 `NETWORK` 与 `RATE_LIMIT`（HTTP 5xx 归入 `NETWORK` 所以有按钮），
`BAD_RESPONSE` / `TOO_LONG` / `AUTH` 不挂按钮。逻辑自洽，但用户看到的是"同样失败、待遇不同"。

### P5 · 手动验收清单第 1 条无法自动化（自动化边界，建议写进文档）

`commands` 里的 `Alt+T` 是浏览器级快捷键，**任何自动化都触发不了**（CDP 合成按键只到渲染进程）。
README 的「手动验收清单」把它当普通步骤写，值得标注"这一条必须真人按键"。

## 6. 台架怎么复跑

```bash
# 一次性：起常驻实例（会弹一次 Chrome 授权框，点「允许」）
JY_QA_KEEP=1 node .qa/daemon.mjs
# 另开终端，各场景复用同一实例
JY_QA_ATTACH=1 node .qa/run-core.mjs     # 整页/还原/缓存/双语/中文页/隐私闸门
JY_QA_ATTACH=1 node .qa/run-live.mjs     # 增量翻译与观察者
JY_QA_ATTACH=1 node .qa/run-errors.mjs   # 错误处理与降级
JY_QA_ATTACH=1 node .qa/run-toast.mjs    # 页面级提示与优先级
```

两个踩过的坑记在这里，省你一遍：**Chrome 137 起品牌版忽略 `--load-extension`**，只能用
`Extensions.loadUnpacked`；而这种方式挂上来的扩展**已授权的 host 权限不随浏览器重启保留**，
所以必须让实例常驻（`daemon.mjs`），否则每轮都要人点一次允许。
