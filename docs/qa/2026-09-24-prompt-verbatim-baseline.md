# 提示词标识符保真度的基线读数：满分，所以那句保留规则不该加

> **实测记录 · 2026-09-24 · 一次被自己的读数推翻的设计。**
> 复跑：`node .qa/prompt-selfcheck.mjs`（纯 Node、零网络、不花额度，证这把尺子能不能红）
> → `npm run build && node .qa/run-prompt-baseline.mjs --runs=8`（要真 Key，读 `.qa/endpoint.json`，
> 会起临时 Chrome 打真实 MiMo）。
> 本文每个分数都是 8 次重复计数的原始读数。**只在一把 Key（`api.xiaomimimo.com` / `mimo-v2.6-flash`）上取得，
> 换供应商不能外推。**

## 起因与结论

设计意图是给 `src/engines/openai-compat.ts` 的 `MULTI_RULES` / `SINGLE_RULES` 各加一句
"代码标识符 / URL / 邮箱 / 时间戳逐字原样输出"，依据是 `docs/qa/2026-09-23-multi-site-report.md:62-105`
里那条 P2/P5（"这类字符串一旦被模型翻译，用户看到的是 `背景-*` 这种废掉的东西"）。

**基线读数不支持这个改动**：10 条硬判据在 8 轮里全部 8/8，标识符本来就原样返回。
加了那句只会抢走"逐字符复制标记"那一句的注意力——而后者是唯一撑着编号协议的东西（见
`docs/qa/2026-09-24-mimo-marker-protocol.md`：换写法就掉到 11/12）。

那条 P2 的真正内容也因此要说清楚：它是**"不该送出去的东西送出去了"**（额度与隐私），
不是"模型把它译坏了"。修法在提取侧，不在提示词。

## 量具：为什么不能直接 fetch 真接口了事

`.qa/measure-latency.mjs` 那类脚本把 system 文本**写死在自己脚本里**——那测的是手抄的一份提示词，
不是产品发出去的那一份。所以这套台架让浏览器里的 `buildMessages` 自己产出请求：

- `.qa/prompt-proxy.mjs` — 监听 **8789** 的透明转发代理，原样转发状态码与响应体，只把真 Key 在
  Node 侧注入（档案里写的是占位串，所以真 Key 不进浏览器、不进 `chrome.storage`、不进任何抓包）。
  不用假引擎的 8787 是因为 `daemon.mjs` 起的 mock 会留孤儿进程占着端口（实测撞上过一次）。
- `.qa/score-prompt.mjs` — 判据。11 条 case：4 段整段就是标识符、3 段纯散文、3 段**标识符夹在句内**、
  1 段半结构（时间戳，只报数不判）。
- `.qa/run-prompt-baseline.mjs` — 串起来跑，产出下面的读数。
- `.qa/fixture/verbatim.html` — 11 段夹具，刻意留在 `maxSegmentsPerBatch=12` 之内，走生产的同一批形状。

### 每条 case 都配了反向判据，因为"全原样返回"能骗过正判据

标识符保真度单独量是没意义的：一句"什么都别译、原样吐回来"能拿满分，而那样等于关掉翻译功能。
所以纯散文那一半要求"必须含汉字且不等于输入"，句内那一类要求"标识符保留 **且** 句子被译"两个条件同时成立。

`.qa/prompt-selfcheck.mjs` 用合成响应把这三条臂各证一次红（22 项，全绿才算数）：

| 变异 | 必须红的是哪半边 |
|---|---|
| 标识符被译走 | 4 条 verbatim 全红 + 3 条 embedded 红（token 没了），prose 不误伤 |
| 整段原样回显（退化实现） | 3 条 prose 全红 + 3 条 embedded 红（token 在但没译） |
| 少一段标记 / 编号乱序 / 空段 | 判成"这一轮降级"，硬判据归零 |
| 单段输出多一个字 | 逐字判据判红（没被"包含"糊过去） |
| 某条 case 根本没送出 | 记为缺失，不算通过 |

**已经抓到过一次真 bug**：判据最初用行锚定的 `^<<<N>>>$` 切响应，而产品
`parseNumberedResponse` 用的是不限定的 `/<<<(\d+)>>>/g`——模型把译文写在标记**同一行**是实测常见输出，
锚定会把好答案误判成"少一段"。尺子比产品严，读数就在测尺子。

三层守卫（`docs/qa/2026-09-24-measurement-traps.md` 总则 3）在这里的落点：
① 11 条已知答案；② 发请求前用 DOM 实际文本核夹具与 `CASES` 一字不差、并验请求里
`Target language: 简体中文 (zh-Hans)` 与段数；③ **DOM 页面显示** 与 **代理抓到的模型输出** 两路对账，
8 轮 × 11 段 = 88 次比对，0 处不一致。

## 基线读数（改前的产品提示词，8 轮 × 真机 × 真 Key）

| case | 类别 | 计数 | 样本 |
|---|---|---|---|
| `v-table` `<table>` | 标识符整段 | **8/8** | `<table>` |
| `v-prop` `overscroll-behavior` | 标识符整段 | **8/8** | `overscroll-behavior` |
| `v-doi` | 标识符整段 | **8/8** | `https://doi.org/10.48550/arXiv.2303.08774` |
| `v-mail` | 标识符整段 | **8/8** | `someone@example.com` |
| `m-prop` | 标识符在句内 | **8/8** | 将 **overscroll-behavior** 设置为 contain 以阻止滚动链式传递。 |
| `m-tag` | 标识符在句内 | **8/8** | **`<caption>`** 元素用于标注数据表的各列。 |
| `m-hook` | 标识符在句内 | **8/8** | 仅在组件首次挂载时调用 **useEffect**。 |
| `p-one/p-two/p-three` | 纯散文（反退化臂） | **8/8** | 工程师常常低估嵌套回调链会消耗多少阅读时间。 |
| `s-stamp` | 半结构，**不判** | 4/8 逐字 | 另 4 轮给出 `[v1] 周三，2023年3月15日 17:15:04 UTC（3,853 KB）` |

标记协议 **8/8 完好、零降级**（一次都是 1 请求 / 11 段，没有拆成逐条）。

唯一有真实不稳定的是那条**没设判据**的：整段是时间戳时，一半概率把 `Wed, 15 Mar 2023` 本地化成
「周三，2023年3月15日」。这是产品判断（日期本地化是好是坏），不是质量 bug，所以留在"不判"。

## 顺带量到的延迟读数：提示词更不是杠杆，但原因和我先前的估计不同

同一批 11 段直连接口的四个变体（`temperature: 0`，各 1 次）：

| 变体 | 耗时 | completion | 其中 reasoning | prompt / cached |
|---|---|---|---|---|
| 现状 | 3587ms | 226 | 14 | 314 / **256** |
| `thinking:{type:'disabled'}` | 3256ms | 226 | 14 | 316 / 256 |
| `enable_thinking:false` | 3969ms | 227 | 15 | 314 / 256 |
| `reasoning_effort:'low'` | 4762ms | 437 | **225** | 314 / 256 |

三件事：

1. **提示词那 314 个输入 token 里有 256 个命中服务商缓存** ⇒ 瘦身省的是本来就不贵的那一侧。
2. **MiMo 确实吐思考链**，所以 `docs/qa/2026-09-23-multi-site-report.md:123-125` 那句
   "不是推理模型，没有思考链在烧时间"只在 DeepSeek 上成立。但在整页批次这个形状上它只占
   226 个输出 token 里的 14 个，**不是延迟主导**（单段那一类占比高：一句 9 个词的英文烧 27 个 reasoning token）。
3. **三个关思考链的参数全被静默忽略**（HTTP 200、usage 不变，最后一个反而把 reasoning 顶到 225）。想省这一笔得另找路子。

真正扎眼的是**方差**：走完整扩展链路的 8 轮单请求是 min 4.2s / 中位 8.1s / **max 37.0s**。
同一份输入能差到 9 倍，这才是"看起来卡死"的来源，而它不在提示词这一侧。

## 台架可复现性的两个门槛（新脚本必撞）

1. **建档之后必须在弹窗里选档**，否则整页每一格都是「还没有可用的翻译引擎」且**一条请求都不发**。
   这是设计（`src/options/sections/engine.ts:629`：设置页从不写 `engineId`），而「测试连接」不依赖它，
   所以"按钮能通、页面全红"这个组合会持续误导人和台架。`run-prompt-baseline.mjs` 的 `selectProfile()` 补了这一步。
2. **译文文字在 shadow DOM 里**：读 `jy-translation.textContent` 永远是空串。第一次跑时它让我把
   产品的真实报错读成了"没有报错文本"，把两路对账做成了永远不一致。已记成
   `docs/qa/2026-09-24-measurement-traps.md` 的坑 #10。

## 没做与边界

- **产品代码一行未改**。这句保留规则的取舍依据已经变成"不做"，改判据要新读数支撑。
- 句内标识符只有 3 条样本、且都是干净的 ASCII 标识符；真正难的混排（同一句里既有 `background-*`
  又有需要意译的 `background`）没有覆盖。
- 只测了目标语言 `zh-Hans`；日文/韩文下的保真度未测。
- 只在 MiMo 上量过。`docs/qa/2026-09-23-multi-site-report.md` 那批 P2/P5 是在别家站点与另一家
  供应商上看到的，**本文证伪的是"MiMo 会把整段标识符译坏"，没有证伪"这些段不该送出去"**——
  后者是提取侧的活，下一步做。
