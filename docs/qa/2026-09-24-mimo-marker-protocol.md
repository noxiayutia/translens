# MiMo 连不上：实测是编号标记没被回显，不是网络（0/8 → 8/8 的完整读数）

> **实测记录 · 2026-09-24 · 供应商行为 + 一处协议设计的收敛。**
> 复跑：`node .qa/run-mimo-real.mjs`（要真 Key，读 `.qa/endpoint.json`，会起一个临时 Chrome 真点按钮）。
> 本文的每个分数都是 8 次或 12 次重复计数的原始读数，不是"试了一次没复现"。

## 现场

用户在设置页点「测试连接」连 MiMo，界面上只有一行：

```
连接失败（BAD_RESPONSE）：模型返回 0 段，期望 1 段
```

这条文案出自 `src/engines/openai-compat.ts` 的 `parseNumberedResponse`，
**不是** `NETWORK` 也不是 `AUTH`：说明 HTTP 200、JSON 合法、`choices[0].message.content` 非空、
Key 和模型名都对。失败发生在**解析模型回显的编号标记**这一步。

顺带排除一个岔路：`platform.xiaomimimo.com`（控制台网页）实测对 `/chat/completions`
返回 **403 + HTML**，会报成完全不同的错。真实接口域名是 `api.xiaomimimo.com/v1`。

## 根因：`mimo-v2.6-flash` 不可靠地回显 `<<<N>>>`

同一请求、`temperature: 0`，各打 8 次：

| 请求段数 | 标记回显通过率 | 失败样本（模型实际返回的 `content`） |
|---|---|---|
| **1 段** | **0/8** | `"1 你好"`、`"1>>>\n你好"`、`"1. 你好"`、`"Hello! How can I help you today? 😊"` |
| 2 段 | 7/8 | `"1. 你好\n2. 世界"` |
| 3 段 | 3/8 ~ 7/8 | 同上；**两次测法给出的分数本身就不一致**（这就是"随机"的证据） |

模型把 `<<<1>>>` 改写成自己的编号格式。`temperature: 0` 下同一输入八次给出八种形状，
说明这个供应商的解码端并不是确定性的。

## 三个被这次实测放大或证伪的设计点

1. **`runConnectionTest` 永远只发 1 段**（`TEST_TEXT = 'hello'`，`options/sections/engine.ts:81`），
   而 1 段恰好是失败率最高的形状 ⇒ 对 MiMo 这个按钮几乎必然报红，与服务是否可用无关。
2. **`scheduler.ts:111` 的注释前提是错的**：「`BAD_RESPONSE` 重试同一个输入没有意义」。
   同一输入的结果是随机的，重问一次往往就过——它被排除在 `RETRYABLE_CODES` 之外，
   恰好排除了一个**该重试**的错误。
3. **降级路径会放大故障**：多段 `BAD_RESPONSE` 降级到 `translateOneByOne`，
   即拆成每次 1 段——正好拆进 0/8 那个形状。所以真实页面翻译不是"退化成慢一点"，
   是整批一起崩。

## 收敛：单段根本不需要编号协议

标记存在的唯一目的，是把 N 条译文拆回原顺序。**N=1 时它是零信息量的负担。**
于是把请求按段数分形：多段继续用标记，单段直接发原文。

换标记形状这条路实测无效（1 段各 8 次）：`[[1]]` 3/8、`<1>` 6/8、`@@@1@@@` 1/8。
唯一有效的提示词改法是在 system 里要求"逐字符复制标记"（1 段 11/12、3 段 12/12），
但**仍不到 100%**，所以没有采用它作为单段的答案。

## 改后读数

**Node 里走生产代码路径 `openAiCompatEngine.translate`**，每种形状 8 次，
判据 = 条数相符 **且** 没有标记/编号泄漏。（这组是临时脚本跑的、跑完已删；
要复跑请直接用下面那条真机命令，它覆盖的是同一个 `translate` 函数。）

| 形状 | 改前 | 改后 |
|---|---|---|
| 单段 `["hello"]`（= 测试连接） | 0/8 | **8/8** |
| 单段长句 | — | 8/8 |
| 2 段（= 降级逐条退成的形状） | 7/8 | **8/8** |
| 12 段（= 整页批次） | 3/8 ~ 7/8 | **8/8** |
| 单段翻成日文 | — | 8/8 |

**真机（临时 Chrome + 真实设置页 + 真鼠标点「测试连接」）：8/8**，状态行 8 次都是
`连接成功：hello → 你好`。

## 这次顺带补上的两处量具

改请求形状会让**任何假设标记存在的替身**静默失真，所以：

- `.qa/mock-engine.mjs`：认两种形状。只认标记的话 `segments` 会把单段数成 0，
  扫描表"段次"整列静默少算（`docs/qa/2026-09-24-measurement-traps.md` 总则 3 那一类）。
- `.qa/mock-engine.mjs` 的 `badmarkers` 模式改成**只破坏带编号的请求**。否则降级逐条
  （全是单段）会把 `<<<1>>>只有一段` 当译文收下，`run-errors.mjs` 的
  「降级后仍然全部译出」会绿，而页面 14 格填的是同一句话。
- `.qa/mock-selfcheck.mjs` 加 4 条断言，并且**都证过红**：
  - 变异 A（量具退回只认标记）⇒ 红 4 条（`segments=0`、译文 `"||"`、`numbered=[true,true,true]`、badmarkers 那条）。
  - 变异 B（`badmarkers` 恢复无条件破坏）⇒ 恰好红 1 条（第 14 项）。
- `tests/background/service-worker.test.ts` 的 `stubEngineFetch` 同样得认两种形状——
  它不认的时候，红的居然是「两层缓存的层次顺序」那两条毫不相干的用例（译文压根没写进缓存）。

全量单测：57 files / 1119 tests 全绿。

## 仍然没做（等裁决，不是遗漏）

1. **`BAD_RESPONSE` 是否进 `RETRYABLE_CODES`。** 上面第 2 条已被实测证伪，但改它会撞红
   `tests/engines/types.test.ts:23` 那条 `[...RETRYABLE_CODES].sort() === ['NETWORK','RATE_LIMIT']`，
   而且无界重试有真实风险：`scheduler.ts:99-106` 已经警告过"抖动 → 整批重发 → 429 → 再整批重发"
   会接成正反馈。要动就得连着"重试预算"一起定，不该由改协议的人顺手定。
2. **其它供应商无法回归。** 手头只有 MiMo 一把 Key。本次的改动对**所有** OpenAI 兼容供应商生效
   （单段免标记、多段加"逐字符复制"、目标语言从裸标签改成 `简体中文 (zh-Hans)`）。
   单段免标记这一条对任何供应商都只会更容易（少一个必须逐字复现的怪符号）；
   多段那句提示词与语言名渲染是纯增量信息。但这是推理，不是实测。
